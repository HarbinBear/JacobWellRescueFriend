## 一、为什么要做这个系统

现有的浮力只有一层：**呼吸浮力**（`BreathSystem.computeBuoyancyOffset()`）。
它由肺容积驱动，玩家**不能主动控制**，作用是给身体一个"跟着呼吸起伏"的生命感，
幅度非常小（终端位移 ±2~3 像素）。

结果是：迷宫模式里"上下移动"这件事，和"左右移动"在操作上完全同质
——都只是把摇杆推向某个方向。**深度不是一个需要被管理的资源，只是一个坐标。**

而真实洞穴潜水里，深度管理是整套技术的核心：
中性浮力、压缩效应、上浮速率、安全停留，全都围绕一件装备展开 —— **BCD**。

这个系统要达成的是：**把"深度"从坐标变成需要持续经营的状态。**

## 二、真实装备与真实操作（调研）

### 2.1 装备构造

BCD（Buoyancy Control Device，也叫 BC / 浮力背心 / wing）是一件带气囊的背心：

| 部件 | 作用 |
|---|---|
| 气囊（bladder） | 尼龙外壳 + 内胆，容量按型号 10~20 kg 举升力 |
| LPI 中压软管 | 从气瓶第一级取气，接到左肩垂下的 inflator 手柄 |
| 充气钮（inflate） | 拇指按下，气瓶的气进气囊 |
| 排气钮（deflate） | 拇指按下，气囊的气从手柄顶端排出（需把手柄举到最高点，气往上走） |
| 肩部排气阀（shoulder dump） | 拉一下 inflator 软管即开，最常用的排气方式，气泡从左肩一大串涌出 |
| 后下排气阀（rear dump） | 倒立 / 头下脚上姿态时用 |
| 超压排气阀 | 内压过高自动溢流，防止气囊爆裂 |

### 2.2 受力分解

潜水员整体的净浮力 = 以下几项相加：

| 分量 | 符号 | 特性 |
|---|---|---|
| 配重铅块 + 装备（气瓶 / 灯 / 工具） | 恒定负 | 不随深度变化 |
| BCD 气囊体积 | 可控正 | 玩家唯一能主动控的量 |
| 湿衣 neoprene 气孔 | 正，**随深度衰减** | 深处被压扁，浮力几乎归零 |
| 肺容积（±2~3 L） | 正，周期振荡 | 微调；本项目由 BreathSystem 承担 |

### 2.3 杀人的那条：玻意耳定律

绝对压力 `P = 1 + 深度/10`（atm）。气囊里的气体**物质量不变**，但体积反比缩放：

```
下潜 → P↑ → 气囊压小 → 浮力↓ → 沉得更快 → 更深 → 更小 → …   不受控下沉
上浮 → P↓ → 气囊膨胀 → 浮力↑ → 升得更快 → 更浅 → 更大 → …   不受控上浮
```

两个方向都是**正反馈**，一旦进入就会自己加速。其中**不受控上浮（runaway ascent）**
是休闲潜水最致命的事故类型之一，直接后果是肺气压伤与重度减压病。
现代教学标准把上浮速率限制在 **9 m/min**（老标准 18 m/min）。

所以真实潜水员在整程都在微调 BCD：

| 阶段 | 操作 |
|---|---|
| 水面待命 | BCD 充满，正浮力漂着 |
| 开始下潜 | **完全排气**，负浮力开始沉 |
| 到达目标深度 | 少量点射充气，找中性 |
| 水中巡游 | **只用呼吸微调**，BCD 不动 |
| 上浮 | **持续小量排气**，控制在 9 m/min 内 |
| 5m 安全停留 3min | 需要精准中性浮力才能悬停不动 |
| 出水面 | 充气浮起来 |

### 2.4 一句话结论（决定了系统的形状）

> **BCD 是粗调，呼吸是微调。**

这句话正好和本项目已有的呼吸浮力形成天然的两层结构，
所以 BCD 不替换任何东西，只是**叠加一层玩家可控的粗调**。

## 三、游戏化物理模型

### 3.1 唯一状态真相

只有一个持久状态量：

```
gasNL —— 气囊内气体的"标准升"（换算到水面 1 atm 下占的体积）
```

它**只被玩家的充/排气改变，不随深度变化**。这是物理上的正确抽象
（气体物质量守恒），也让整个系统只有一个可存档量。

### 3.2 每帧派生

```
P     = 1 + depth / depthPerAtmMeters                  绝对压力（atm）
volL  = gasNL / P                                      玻意耳：实际体积（升）
suit  = suitLiftSurfaceL / P                           湿衣浮力，同样被压缩
a_y   = baseSinkAccel − (volL + suit) × liftAccelPerLiter
```

`a_y > 0` 下沉（+Y）；`a_y < 0` 上浮（−Y）。每帧 `player.vy += a_y`。

### 3.3 中性浮力所需体积（UI 上那条会动的黄线）

```
neutralVolL(depth) = baseSinkAccel / liftAccelPerLiter − suitLiftSurfaceL / P
```

关键性质：**它随深度增大**（湿衣越深越不给力）。

| 深度 | P | 中性所需体积 |
|---|---|---|
| 水面 | 1.0 | 1.14 L |
| 6.5 m（入水点） | 1.65 | 1.34 L |
| 30 m | 4.0 | 1.51 L |

于是玩家下潜时会**同时**看到两件事：

- 气量条自己往下掉（气被压缩：1.34 L → 0.55 L）
- 中性黄线自己往上爬（湿衣失效：1.34 L → 1.51 L）

两条线越拉越开 —— 这就是玻意耳定律的可视化，比任何文字教程都有效。

### 3.4 充排气：体积流量而非物质量流量

刻意选择"按实际体积流量推进"，再换算回标准升：

```
充气：ΔvolL = inflateRateLPerSec × dt;  ΔgasNL = ΔvolL × P
排气：ΔvolL = deflateRateLPerSec × dt;  gasNL  = volL × P
气瓶消耗 = ΔgasNL × o2PerNL
```

两个好处同时成立：

1. **操作可预期**：不管在什么深度，"按住一秒"得到的浮力变化恒定。
   如果用物质量流量，玩家在 30m 按一秒只有水面的 1/4 效果，手感会非常糟。
2. **深处充气更费气瓶自动涌现**：同样的体积在 30m 需要 4 倍标准升，
   所以"该配平的时候一次配平好，别在深处反复大口充排"这条真实的耗气纪律
   不需要额外规则去教，玩家自己会算。

### 3.5 数值标定

标定基准：`waterDrag = 0.98` → 终端速度 = 加速度 ÷ 0.02 = 加速度 × 50；
`mazeTileSize = 120 px = 1 米` → 1 px/帧 = 0.5 m/s = 30 m/min。

| 场景 | 净加速度 | 终端速度 | 换算 | 评价 |
|---|---|---|---|---|
| 完全排空 · 水面 | +0.0139 | 0.70 px/帧 | 0.35 m/s | 正常快速下潜 |
| 完全排空 · 30 m | +0.0185 | 0.93 px/帧 | 0.46 m/s | 湿衣被压扁，更沉 |
| 配平良好 | ≈ 0 | ≈ 0 | 悬停 | 目标状态 |
| 充到量表满格 · 30 m | −0.0120 | 0.60 px/帧 | **18 m/min** | 刚好踩到危险阈值 |
| 充到容量上限 · 30 m | −0.0303 | 1.50 px/帧 | **45 m/min** | 严重失控 |

参考：玩家主动游泳速度约 4 px/帧，所以浮力是"背景漂移"级别的力
——足以让你必须持续关注，但不会剥夺操作权。

### 3.7 手动挡下的姿态耦合（涌现出来的真实感）

上表按**自动挡**（默认档）标定，自动挡用各向同性的 `CONFIG.waterDrag = 0.98`。

手动挡（`manualDrive.enabled = true`，玩家可在 HUD 切换）用的是**各向异性阻力**：
`dragForward = 0.975`（沿身体朝向，流线型）/ `dragLateral = 0.9`（垂直身体朝向）。
于是浮力的实际效果开始取决于**身体朝向**：

| 手动挡姿态 | 垂直方向走哪个阻力 | 终端速度倍率 | 满气 30m 上浮 |
|---|---|---|---|
| 身体水平（横着巡游） | dragLateral 0.9 | ×10 | 0.15 m/s ≈ 9 m/min |
| 身体竖直（头朝上/下） | dragForward 0.975 | ×40 | 0.60 m/s ≈ 36 m/min |

这**不是 bug，而是应该保留的涌现行为**：真实潜水里遇到上浮过快，
标准处置之一就是"摊平身体（flare out）增大迎水面积来刹车"。
手动挡玩家会自己发现"横过来能压住失控上浮"，这是免费送的深度技巧。

所以不要为手动挡加任何阻力补偿。要调只调 `CONFIG.diver.dragLateral`。

### 3.6 惩罚闭环：刻意不新增失败分支

失控上浮时，每秒往减压系统的 `nitrogenLoad` 追加 `ascentNitrogenPerSec`
（`DecompressionSystem.addNitrogenLoad()`）。于是：

```
忘记排气 → 越升越快 → 氮负荷飙升 → 跨过黄线 → 减压任务锁定
        → 不做完 12/9/6/3m 停留就出水 → 已有的重度减压病失败分支
```

这条链完全复用 P15 已经做好的东西，一个新失败类型都没加，
而且**因果关系与真实医学一致**（上浮过快正是 DCS 最主要的诱因）。

## 四、交互方案

### 4.1 控件形态：一根竖直的 inflator 手柄

原型直接来自真实装备：从左肩垂下来的充气管手柄，拇指在上面上下拨。

```
        ┌──────┐
        │  ＋  │   充气钮：气进气囊 → 上浮
        ├──────┤
        │ ▓▓▓▓ │   气囊量表（实际体积）
        │ ┈┈┈┈ │ ◀ 中性刻度线（黄，会随深度上移）
        │ ▓▓▓▓ │ │ 右侧细条 = 净浮力方向与强度
        ├──────┤
        │  －  │   排气钮：气出气囊 → 下沉
        └──────┘
              ▲ 屏幕右侧，竖向中心 0.52 ch
```

位置选择理由：右手拇指自然可达；避开左下撤离按钮（0.18 cw, 0.88 ch）、
右下轮盘按钮（cw−112, 0.88 ch）、左上 HUD 竖列、右上探知仪雷达点。

### 4.2 三条不可妥协的设计约束

**① 方向语义必须服从屏幕直觉，而不是真实握持姿态。**
真实装备上充气钮反而在下面（因为手柄是倒握的），但屏幕上必须
"按上面的钮身体往上走"，否则玩家永远建立不起条件反射。

**② 中性刻度线必须画成会动的。**
这是整个系统唯一的教学载体。静态刻度线会让玩家误以为"填到某个固定高度就行"，
彻底丢掉玻意耳这层。

**③ 净浮力必须与气量分开显示。**
玩家真正要控的不是"气量"而是"净浮力 = 0"。所以量表右侧另挂一根中心为零的双向条：
绿色向上 = 正在被托起，橙色向下 = 正在被拽沉。
完全归中时整根手柄亮一圈青色呼吸光环，给正反馈。

### 4.3 操作手感

| 动作 | 行为 |
|---|---|
| 按住不放 | 持续充/排气 |
| 轻点一下 | 一个 short burst（`minBurstSec` 补足，真实潜水员就是点射） |
| 手指滑出按钮 | 立刻视为松手（真实拇指离钮就断气） |
| 两颗钮同时按 | 排气优先（真实处置原则：先止住失控） |
| 左手推摇杆 + 右手排气 | 同时成立（BCD 触点从不登记进 manualDrive / joystick） |

### 4.4 视觉反馈层级

| 层 | 内容 |
|---|---|
| 控件 · 按钮 | 按下时外扩脉冲光环 + 图标高亮；充气钮上方三道进气流短线抖动；排气钮下方三个气泡向上飘 |
| 控件 · 量表 | 填充色按"离中性有多远"变化（青绿=配平 / 亮蓝=偏正 / 暗蓝灰=偏负）；液面微弱晃动高光；顶部溢流三角闪烁 |
| 控件 · 数值 | 底部 `x.x ATA` 显示当前绝对压力（玻意耳的自变量） |
| 世界 · 潜水员 | 躯干外层画一层气囊（`RenderDiver.drawBCDBladder`）：气越多囊越鼓、边缘越亮、织带被撑开；左肩排气阀在排气时亮起 |

| 音效 | 复用 `collisionBreath`（BreathBubble.mp3）作一次性嘶气声，按 `sfxIntervalMs` 重复：充气 rate 1.7（尖锐小口径进气）/ 排气 rate 1.25（闷粗大口径排水） |

### 4.5 教学节奏

1. **每次下潜前 5 秒**：控件左侧浮一张小卡片"浮力背心 / ＋充气上浮 / －排气下沉 / 黄线＝中性"，淡入淡出自动消失。
2. **首次深度超过 `tutorialDepth`（12 m）**：推一条剧情文字
   "⚠ 深度增加，浮力背心里的气被压缩了 / 右侧 ＋ 补气维持中性，－ 排气下沉 / 上浮时务必持续排气，否则会失控飞升"。
3. **之后全部靠视觉自解释**（两条线拉开 + 净浮力条偏移 + 边缘告警）。

## 五、与其他系统的咬合

| 系统 | 咬合方式 |
|---|---|
| **呼吸浮力**（BreathSystem） | 保留不动。BCD 粗调 + 呼吸微调两层叠加到 `player.vy`，与真实潜水分工一致 |
| **减压停留**（DecompressionSystem） | 双向：① 减压停留要求 `\|vy\| < 0.8` 持续数秒，逼玩家必须先把 BCD 配平好才做得完；② 失控上浮往 `nitrogenLoad` 灌，形成惩罚闭环 |
| **氧气经济** | 充气从气瓶取气，深处更贵。反复大口充排会显著吃掉下潜时长 |
| **潜水衣极限深度** | 超深时氧耗 ×3 会连带放大 BCD 充气成本（同一个 `o2Consumption` 通道） |
| **背包 / 商店 / 全屏页** | 全屏页打开时 `bcdReleaseAll()` 强制松钮，避免"幽灵按住态"一直漏气 |
| **主线 / 竞技场** | 完全不启用（`shouldBeActive()` 只认 `mazeRescue` + `phase === 'play'`） |

## 八、典型陷阱（后续接手必读）

1. **`resetBCDSystem()` 必须在 `player.y` 被写成出生深度之后调用。**
   `initialFillMode: 'neutral'` 要按入水深度反算中性气量，位置没定好就会预充错气。
   当前放在 `startMazeDive` 的 `snapCameraToPlayer()` 之后。

2. **`gasNL` 是唯一状态真相，`volumeL` 是派生量。**
   GM action 改状态时必须同时写 `gasNL = volL × pressureAtm`，
   否则下一帧 `volumeL = gasNL / P` 会把你的修改冲掉。

3. **充排气必须按体积流量、气瓶消耗必须按标准升。**
   两边都用同一种单位会丢掉"深处充气更贵"或者"深处按一秒没反应"其中之一。

4. **BCD 触点绝不能登记进 `manualDrive.activeTouches`。**
   touchStart 命中后必须 `continue`，否则玩家想排气结果人游走了。
   反过来 touchMove 里刻意**不** early-return，才能让"左手摇杆 + 右手排气"并行。

5. **全屏页 / GM 面板抢占触摸后不会再回调 touchEnd。**
   所有这类分支都要调 `bcdReleaseAll()`，否则会留下永久漏气的幽灵按住态。

6. **失控判定必须带 `netAccel` 方向条件。**
   只看 `|vy|` 会把"玩家主动往上游"误判成失控（玩家游泳速度约 4 px/帧，
   远大于 0.55 的告警阈值）。当前条件是 `netAccel < −deadzone && vy < −ascentWarnSpeed`。

7. **`drawBCDBladder` 必须画在躯干填充之前。**
   画在之后会盖住身体、气瓶和手臂，看起来像套了个塑料袋。

8. **不要给 BCD 单独做失败分支。**
   惩罚全部经由 `addNitrogenLoad` 流进减压系统，
   这样"失控上浮"和"跳过减压"共用同一套结算与视觉，不会出现两套语言。

9. **不要为手动挡的阻力差异做补偿。**
   手动挡各向异性阻力导致"横着漂得慢、竖着冲得快"是应该保留的涌现真实感（见 §3.7），
   加补偿会同时杀掉"摊平身体刹车"这个免费的深度技巧。

## 九、后续扩展点（本版刻意没做）

| 扩展 | 说明 |
|---|---|
| **BCD 装备化** | 加 `bcd` 装备槽：`bcdBasic`（保底 4 L）/ `bcdTech`（6 L + 排气更快 + 溢流阀更宽容）。需要动 `ExtractionRegistry.EquipmentEffects`（加 `bcdCapacityL` / `bcdDeflateMul`）、`Loadout.autoSelectBestEquipment` 的 `pickBest`、商店货架池。第一版先不做，避免同时改动经济系统 |
| **配重可选** | 让玩家在出发准备页选铅块重量，直接改 `baseSinkAccel`。轻配重更省气但深处压不住，重配重好下潜但要一直充气 |
| **干衣（drysuit）** | 干衣有独立的进排气阀，等于第二套 BCD。可以作为高级潜水衣的差异化能力 |
| **失控上浮的独立结算文案** | 目前统一走 deco 失败页。未来可以按 `surfacingReason` 细分出"肺气压伤" |
| **BCD 卡阀故障事件** | 真实事故：充气钮卡住持续进气。可以做成随机事件，逼玩家断开 LPI（长按排气 3 秒）自救 |
| **结算页展示** | `getBCDO2SpentTotal()` 已就绪，可以在 debrief 加一行"浮力控制耗气 X"，让玩家看到自己的配平效率 |
