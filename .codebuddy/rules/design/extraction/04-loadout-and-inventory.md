## 一、整体数据模型

撤离玩法相关的数据全部挂在新增的 `state.extraction` 子树上，与现有 `state.mazeRescue` **物理隔离**（不要污染现有 mazeRescue）。

```
state.extraction = {
  coins: number,                     // 金币
  reputation: number,                // 名声
  
  warehouse: WarehouseItem[],        // 仓库（卖货前的库存）
  
  consumables: { [id: string]: number },   // 消耗品库存（airTankM: 3）
  emergencies: { [id: string]: number },   // 应急品库存（beacon: 1）
  
  ownedEquipment: string[],          // 已拥有的永久装备 id 列表
  equippedBag: string,               // 当前装备的背包 id
  equippedFins: string,              // 当前装备的脚蹼 id
  
  loadout: {                         // 出发准备页的当前选择
    airTank: string | null,          // "airTankM"
    battery: string | null,
    rope: string | null,
    emergencies: (string|null)[],    // 长度 2，应急槽
  },
  
  shop: {                            // 商店当前货架快照
    consumableShelf: ShopSlot[],
    emergencyShelf: ShopSlot[],
    equipmentShelf: ShopSlot[],
    specialShelf: ShopSlot[] | null,
    refreshCount: { [shelfId: string]: number },  // 当次进店的刷新次数
  },
  
  bag: {                             // 下潜中的临时背包（运行时）
    maxSlots: number,                // 由 equippedBag 决定
    items: BagItem[],                // 拾取的战利品
  },
  
  diveSession: {                     // 本次下潜的临时数据，结束清空
    appliedEffects: { ... },
    pickedRelicIds: number[],
  }
};
```

> ⚠️ **存档键独立**：与 maze_save_v3 分开，使用新键 `extraction_save_v1`。详见 [07-engineering-isolation.md](./07-engineering-isolation.md) §3。

## 二、仓库（Warehouse）

### 2.1 仓库是什么

撤离上岸后，背包里的所有战利品**自动转入仓库**。仓库是"未卖出的库存"。
玩家可以选择：
- 一件一件卖
- 全部一键卖
- 留着不卖（万一商店回购挂出来呢？）

### 2.2 仓库容量

**首版无上限**，简化设计。
未来如果要做"仓库容量"作为新升级目标（比如"仓库扩容到 30 件"），再加。

### 2.3 仓库 UI

全屏页，复用图鉴页的羊皮纸风格，但是网格布局：

```
┌──────────────────────────────────────────────────────┐
│  ◀ 返回    我的仓库              💰 350 金            │
│                              [全部卖出 = +1240 金]   │
├──────────────────────────────────────────────────────┤
│  按 [全部] [古物] [按价格] [按品相] 筛选                │
│                                                      │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐       │
│  │完美  │ │磨损  │ │完好  │ │残缺  │ │普通  │       │
│  │怀表  │ │硬币  │ │骸骨  │ │陶碗  │ │海螺  │       │
│  │840金 │ │6金   │ │525金 │ │16金  │ │18金  │       │
│  │[卖出]│ │[卖出]│ │[卖出]│ │[卖出]│ │[卖出]│       │
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘       │
│  ...                                                 │
└──────────────────────────────────────────────────────┘
```

每件物品卡片显示：
- 缩略图（已有 RenderRelic.ts 的 32 个矢量绘制函数）
- 品相 + 物品名（"完美的怀表"）
- 当前估价
- [卖出] 按钮 / 长按出"详情 / 留着 / 卖出"菜单

### 2.4 排序与筛选

- 按价格：方便"先卖最贵的"
- 按品相：方便"展示完美收藏"
- 按古物分类：方便玩家做收藏感觉

## 三、出发准备页

### 3.1 触发时机

岸上界面玩家点"下潜" → 不是直接进迷宫，而是先进**出发准备页**。
准备页确认后才真正开始下潜。

### 3.2 页面结构

```
┌──────────────────────────────────────────────────────┐
│  ◀ 取消              出发准备                         │
├──────────────────────────────────────────────────────┤
│                                                      │
│  必备                                                │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐ │
│  │ 氧气瓶      │  │ 手电电池    │  │ 绳索        │ │
│  │ [中×3 库存] │  │ [标×2 库存] │  │ [5段×1库存] │ │
│  │ ▼ 选择      │  │ ▼ 选择      │  │ ▼ 选择      │ │
│  └─────────────┘  └─────────────┘  └─────────────┘ │
│                                                      │
│  应急（最多 2 件）                                   │
│  ┌─────────────┐  ┌─────────────┐                   │
│  │ 救生信标    │  │ [空]        │                   │
│  │ [×1 库存]   │  │ ▼ 选择      │                   │
│  └─────────────┘  └─────────────┘                   │
│                                                      │
│  装备（不可换，去仓库换）                            │
│  背包：8 格   脚蹼：竞速款                          │
│                                                      │
│  ──────────────                                      │
│  本次出发将消耗：                                    │
│    中氧气瓶 ×1 / 标准电池 ×1 / 绳索5段 ×1            │
│    救生信标 ×1                                       │
│                                                      │
│              [ 确认出发 ▶ ]                          │
└──────────────────────────────────────────────────────┘
```

### 3.3 装备选择规则

- **氧气瓶 / 电池 / 绳索**：必选，从消耗品库存里选一件
- **应急槽**：可选，最多 2 件，不选也行
- **背包 / 脚蹼**：在准备页**只显示，不能换**——换的话回岸上仓库换
- 库存不足时该项目灰显，玩家点"商店购买" → 跳转商店

### 3.4 默认行为

- 第一次玩：默认装小氧气瓶（兜底品） + 弱电池 + 没有绳索 + 无应急
- 此后：**记住上次的选择**，自动填充（库存够的话）

### 3.5 取消行为

- 点"取消"或返回 → 回到岸上 → 不消耗任何东西
- 只有点"确认出发" → 立刻扣消耗品库存 → 进入下潜

## 四、下潜中的背包系统

### 4.1 背包容量

由 `equippedBag` 决定（4 / 8 / 12 / 16）。

### 4.2 拾取交互

#### 4.2.1 走近物品

玩家进入物品 80px 范围内，物品上方浮一个**透明轮盘按钮**（与现有氧气瓶轮盘风格统一）。
按钮中心显示物品图标 + 占用格子数。

#### 4.2.2 按住拾取

按住轮盘 0.6 秒（可在 GM 调）→ 进度条转一圈 → 物品**飞入背包**：
- 物品从世界坐标飞向 HUD 右下角背包槽
- 复用 `OxygenTank.ts::FlyingTank` 的飞行轨迹和动画
- 背包槽位"咔哒"一声入位

#### 4.2.3 背包满

如果背包没有足够空格容纳此物品（占 3 格但只剩 2 空）：
- 轮盘变成红色 + 提示"背包已满"
- 玩家长按物品 → 弹"丢弃 / 取消"菜单
- 选择丢弃后重新尝试拾取

### 4.3 拾取成功后场景物如何处理

物品被捡走后：
- 立刻从场景里消失
- 本次下潜内不再出现
- 下次下潜时，按 seed + 派生槽位**重新刷一个**（不一定是同一个 kind，是池子里随机抽）
- 已加入图鉴的 kind 不影响场景刷新概率

### 4.4 HUD 背包格子

下潜中右下角显示：

```
┌─────────────────┐
│ 背包 4/8        │
│ ┌─┐┌─┐┌─┐┌─┐   │
│ │硬││瓶││陶││ ││   │
│ ├─┤├─┤├─┤├─┤   │
│ │  ││  ││  ││  │   │
│ └─┘└─┘└─┘└─┘   │
└─────────────────┘
```

- 已占用格子显示物品缩略图
- 长按格子 → "丢弃 / 详情 / 取消"
- 点击 HUD 背包图标 → 全屏背包页（看品相、估价等详情）

### 4.5 全屏背包页（下潜中）

战时也能查看：
- 显示所有物品的品相和估价
- **不能卖货**（卖货是岸上行为）
- 可以"丢弃"以腾位
- 退出页面回到下潜

## 五、装备效果应用

### 5.1 应用时机

下潜启动瞬间（点"确认出发"后）：

```
1. 锁定本次 loadout，扣消耗品库存
2. 应用永久装备效果到 CONFIG.maze.* 临时副本
3. 应用消耗品效果（如 airTankL → 起始氧气）
4. 应用应急品挂在 player 上（不应用效果，等触发）
5. 进入下潜
```

### 5.2 卸载时机

下潜结束（任何方式）：

```
1. 恢复 CONFIG.maze.* 默认值
2. 计算本次结算（见 §6）
3. 战利品入仓库 / 失败丢失
4. 应急品如果没用，不返还（已带出门 = 用了）
5. 进入结算页
```

### 5.3 应急品触发

应急品在下潜中由玩家手动触发：
- HUD 应急槽显示 2 个图标
- 点击应急图标 → 长按 1 秒确认 → 触发效果
- **救生信标**：触发后立刻进入 surfacing → 完整撤离
- **防鲨喷雾**：触发后所有食人鱼进入"恐惧"状态 30 秒
- **应急氧气片**：触发后 player.o2 += 30

触发的应急品**消耗掉**，下潜结束不返还。

## 六、撤离结算

### 6.1 结算页扩展

`mazeUI/debrief.ts` 现有结算页加入"撤离结算"区段：

```
... 现有的本次新发现图鉴 ...
... 本次新增图鉴种类（金色） ...

──── 撤离结算 ────

撤离方式：完整撤离 ✓ 
  / 半成功撤离 ⚠ 
  / 信标紧急撤离 ★ 
  / 撤离失败 ✗

本次收获：
  完美怀表 ×1 ............... 840 金
  磨损硬币 ×3 ............... 19 金
  完好骸骨 ×1 ............... 525 金
                总计：1384 金

[半成功时显示]
呛水丢失：
  普通陶罐 ×1 ............... -12 金
  残缺玻璃瓶 ×1 ............. -6 金

消耗品已使用：
  中氧气瓶 ×1 / 标准电池 ×1 / 绳索5段 ×1 / 救生信标 ×1

──── 结算 ────
本次净收益：+1366 金
本次成本：-220 金
名声变化：+0  /  +50（救援成功时）
```

### 6.2 失败页

`fishkill` 分支的失败页扩展：

```
案件结案 · 搜寻终止

行动报告...

──── 资产损失 ────

撤离失败：100% 战利品丢失
  完美怀表 ×1（840 金）
  完好骸骨 ×1（525 金）
  ...
  共计 1384 金的物品永久消失

[黑色幽默小字]
"它们将永远沉睡在那张地图深处。"

──── 但你保住了 ────

✓ 你的金库（350 金）
✓ 你的所有永久装备（8 格背包 / 竞速脚蹼）
✓ 本次下潜照到的 3 种新图鉴

[ 接受新的任务 ▶ ]
```

> 这种结算页设计的目的是**强调正向资产**，让玩家失败时也有"我没白潜"的感觉。这是温和撤离玩法的关键 UX。

## 七、岸上营地新入口

岸上 UI（`shore.ts`）顶部状态栏增加：

```
[图鉴 8/32]  [💰 350 金]  [☆ 名声 0]
```

底部 / 侧边新增三个入口按钮（保持手绘风格）：

- 📦 仓库
- 🏪 商店
- ⚙ 装备（背包/脚蹼切换）

这三个入口也作为撤离玩法的功能曝光点，新玩家一眼能看到"这游戏还能做这些"。

## 八、UX 流程示例（首次玩家）

```
1. 玩家点"开始迷宫模式"
   → 教程提示：你是雅各布井的救援者，每次下潜前要做装备准备
   → 自动给 100 金 + 兜底装备
   
2. 进入岸上
   → 引导箭头指向商店：先去看看老板有什么
   → 玩家点商店
   
3. 进入商店（首次进入特殊话术）
   → 老板："第一次见你来。这就是这条洞穴的全部门面..."
   → 玩家可买可不买
   → 退出商店
   
4. 玩家点"下潜"
   → 进入出发准备页（首次进入也有教程）
   → 默认填充小氧气瓶 + 弱电池（库存有）
   → 玩家点"确认出发"
   
5. 下潜中
   → 走过 Relic → 出现拾取轮盘
   → 第一次按住拾取 → 教程：这是战利品，撤离上岸后能卖钱
   → 拾取后 HUD 背包显示
   
6. 撤离回岸
   → 结算页：本次收获 30 金（小新手）
   → 自动入仓库
   → 玩家可选"全部直接卖出"快捷按钮 → 30 金到账
   
7. 重新进店
   → 货架已刷新（自动）
   → 玩家用积累的 130 金买中氧气瓶（40 金）
   → 余 90 金，再下潜
   
8. ... 循环 ...
```

## 九、待确认问题

1. **拾取按住时长 0.6s 是否合适**？
   - 太短 → 玩家走路不小心就捡了
   - 太长 → 拾取太累
2. **背包格子里的物品是否要按"先来后到"排列**？
   - 还是按价格 / 体积自动排序
   - 排序方式影响半成功丢失的"前半丢"还是"后半丢"
3. **应急槽 2 个是否合理**？
   - 当前 2 个，可以再扩到 3 个（应急玩家专属）
   - 但应急品本身不便宜，2 个已经是 230 金成本
4. **下潜中的全屏背包页是否必做**？
   - 不做的话 HUD 格子条要显示更多信息（缩略图 + 估价）
   - 做的话工程量多 1 个页面
5. **半成功撤离的"丢失动画"如何表现**？
   - 是不是该有"呛水甩落物品"的视觉效果
   - 难度不大但需要美术资源

## 十、与现有系统的隔离要点

- **不修改 `state.mazeRescue`**：所有撤离数据放新建的 `state.extraction`
- **不修改 `Relic.ts` 的发现逻辑**：图鉴解锁仍是"手电照到"
- **拾取交互独立成模块**：`ItemPickup.ts`，不污染 `OxygenTank.ts`
- **存档独立**：`extraction_save_v1` key，与 maze_save_v3 隔离
- **HUD 独立**：新建 `RenderInventoryHUD.ts`，与现有 `HUDTopLeft.ts` 不冲突

详见 [07-engineering-isolation.md](./07-engineering-isolation.md)。
