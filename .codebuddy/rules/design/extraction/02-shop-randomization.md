# 02 — 商店：黄金矿工式有限随机刷新

> **本卷优先级：🔴 最高**
> 商店是经济循环的瓶颈控制阀，决定了节奏。
> 物品属性请先读 [01-item-attributes-and-config.md](./01-item-attributes-and-config.md)。

---

## 一、设计核心

### 1.1 摒弃"全面交易行"模式

之前的草案设想商店是一个"所有商品都能买"的全列表，这是错的。原因：

- 选择过多 → 玩家麻木 → 没有"今天必须买什么"的紧迫感
- 没有重玩稀缺性 → 经济曲线失控

### 1.2 借鉴《黄金矿工》的有限随机刷新

《黄金矿工》的商店机制：**每关结束之间能买的道具是从池子里随机出 3~5 个**，玩家在有限选项里做最优解。
这种"今天就这几件，要不要买全凭你"的紧迫感是商店玩法的灵魂。

### 1.3 类似机制还有

- **杀戮尖塔**（Slay the Spire）的商店：每次进商店物品列表是随机抽的
- **以撒的结合**（Isaac）的商店房：一次刷出 2~3 件随机物品
- **流放之路**（PoE）的商人 Niko：每次刷新看运气

这些机制的共性：
1. 物品池是**全集**，但**单次曝光是子集**
2. 子集刷新有**时间/事件门槛**，不能任意刷
3. 玩家需要**在限制下做权衡**，错过就要等

## 二、商店刷新机制

### 2.1 刷新触发

商店货架在以下时机刷新：

| 触发 | 行为 |
|---|---|
| 初次进入岸上（首次新地图） | 立即刷一组初始货架 |
| 每次完成一次下潜 | 撤离回岸的瞬间，下次进商店看到新货 |
| 主动调用"换一批"（消耗成本） | 见 §3 |
| 救援成功 | **额外**刷一组特殊货架（限时） |

### 2.2 货架结构

商店分为 4 个**独立货架**，每个货架按自己的池子刷新：

| 货架 | 槽位数 | 物品池 | 关键作用 |
|---|---|---|---|
| **消耗品架** | 3 | airTank* / battery* / ropePack* | 每次下潜的必需品 |
| **应急架** | 2 | beacon / sharkSpray / airTablet | 保命 / 撤离保险 |
| **永久装备架** | 1 | bag* / fins*（已拥有的不出现） | 长期升级 |
| **特价架** | 1~2 | 任意物品（含古物回购） | 惊喜窗口 |

每次刷新，每个货架按池子独立 roll，**互不影响**。

### 2.3 槽位填充规则

每个货架槽位按"加权随机抽签 + 抽到不重复"填充。

**消耗品架** 3 个槽位：
- 池子里有 8 个候选（airTank S/M/L、battery W/Std/H、rope 5/15）
- 每次刷新随机抽 3 个不重复
- 同一档位不会同时出现两次（不会刷两个"中氧气瓶"）

**应急架** 2 个槽位：
- 池子里有 3 个候选
- 每次刷 2 个不重复

**永久装备架** 1 个槽位：
- 池子里有 7 个候选，但**已购买的从池子里剔除**
- 直到玩家拥有所有装备，这个货架才空

**特价架** 1~2 个槽位：
- 70% 概率出现一件**当前已有库存物品的回购**（鼓励玩家卖货）
- 20% 概率出现一件**消耗品打折**（5~7 折）
- 10% 概率出现一件**装备打折**（8~9 折，已拥有的依然剔除）
- **特价架 30% 概率本次不出现**（增加期待感）

### 2.4 价格波动

每个上架物品在显示时附带一个**价格修正**：

- 90% 概率：原价
- 5% 概率：8 折（绿色"特价"标签）
- 5% 概率：12 折（红色"溢价"标签，"老板：今天进货成本高"）

价格修正与"特价架"是两套独立机制：
- 特价架的折扣是**架本身**的属性
- 普通架上偶尔的特价/溢价是**单品**的属性

## 三、"换一批"机制

### 3.1 设计目标

不强迫玩家"必须买这批" / "必须等下一次下潜"。给一个**有成本的刷新选项**，让玩家在着急买装备时有出路。

### 3.2 刷新成本

- **第一次换**：免费（每次重新进商店都有 1 次免费换货机会）
- **第二次换**：20 金
- **第三次换**：50 金
- **第四次及以后**：100 金，价格固定

成本随刷新次数递增，避免玩家无脑刷出史诗物。
退出商店再回来 → 计数清零，但货架本身不重置（不能利用退出再进来洗）。

### 3.3 仅刷一个货架

允许玩家**只刷某一个货架**，价格按 §3.2 但减半（10/25/50）。
比如玩家只想换"应急架"看看有没有救生信标，就花 25 金单刷该架。

具体表现：3 个槽位先抽 1 个 freeTier，剩下 2 个再走加权随机。

## 六、刷新过程的视觉反馈

刷新瞬间要有"翻牌感"，强化随机性体验：

- 玩家点"换一批" → 货架卡片**翻面**（300ms 翻转动画）→ 显示新物品
- 翻新到稀有物（rare 以上）→ 卡片描边发金光 + 一声"叮"的提示音
- 翻新到特价 → 卡片角标贴一个"特价"红色斜贴纸

复用现有 `surfacing` 弹射上浮的动画工程基础（已有的卡片入场缩放/旋转 ease 函数），不用新写。

## 七、与"老板话术"系统的接口

### 7.1 话术由"上下文标签"决定

- 玩家段位（金币 < 100 / 100~500 / 500~1500 / 1500+）
- 是否刚完成救援（最近 1 次下潜含救援成功）
- 是否破产（金币 < 10）
- 是否首次进店（新存档）
- 当天刷新次数（≥ 3 次时换"老板嫌烦了"）

每个标签组合对应一组话术池，随机抽一句显示。

### 7.2 话术池草案（示例）

```json
{
  "first": ["第一次见你来。这就是这条洞穴的全部门面了，没什么大库存。"],
  "broke": ["要不你先去捡几枚硬币回来？老板我也不富裕。"],
  "midTier": ["这批新到的电池，挺亮。"],
  "rich": ["大主顾来了。今天给你看看压箱底的好货。"],
  "afterRescue": ["听说你今天救了人。这件喷雾算我送你的折扣。"],
  "spammingRefresh": ["……行行，你都换四次了。再换可得加钱。"]
}
```

未来策划可以扩充话术池，每个标签下放十几句，老板就有"性格"了。

## 八、回购系统（特价架）

### 8.1 回购物品的来源

特价架有 70% 概率出现一件"回购品"，意思是：

> 老板把**别人卖给他的某件物品**重新挂出来，问玩家要不要买回去。

物品来源：
- 玩家自己之前卖给老板的（按 1.2~1.5 倍**加价回购**）
- 系统模拟生成的"其他玩家"卖的（虚构 NPC 来源叙事）

### 8.2 设计意义

- 让"卖货"不是单向操作，而是**有可能后悔的**
- 给玩家"哎我之前那件水晶老板挂出来了，要不要买回去"的纠结
- 价格 1.2~1.5 倍是"老板赚的差价"，符合常理

### 8.3 防止刷货架经济

- 同一件物品回购出现后被买走 → 池子里删除
- 玩家立刻再卖 → 不能立即在下次刷新出现，至少间隔 3 次刷新
- 价格修正系数固定，不和普通价格波动叠加

## 九、待确认的开放问题

1. **货架数量是否合适**？
   - 当前 4 个货架（消耗/应急/装备/特价），UI 上一屏能看完？
   - 如果太多可以合并为 3 个（消耗+应急合并）
2. **刷新成本曲线**？
   - 当前 0/20/50/100，是否需要更陡（避免无脑刷史诗）
3. **特价架是否要做**？
   - 特价架是惊喜机制，但增加复杂度
   - 极简方案是只做 3 个货架，去掉特价
4. **回购系统是否要做**？
   - 这是高级机制，首版可不做
   - 但回购系统能让"卖货"产生情感波动，是叙事亮点
5. **货架刷新与下潜次数的耦合度**？
   - 当前是"每次下潜结束都刷"
   - 是否要做"连续 3 次不下潜不刷"的反挂机机制？
6. **老板话术是否首版必做**？
   - 不做也能跑通，但有了话术就有了人味
   - 建议第一阶段做"段位 + 救援 + 破产" 3 个核心话术池

## 十、实现建议（提示工程层）

### 10.1 货架刷新算法骨架（伪代码）

```typescript
function refreshShelf(shelfId: string, ownedSet: Set<string>): ShopSlot[] {
  const cfg = SHOP_POOL.shelves[shelfId];
  const pool = cfg.pool.filter(id => !cfg.excludeOwned || !ownedSet.has(id));
  const slots: ShopSlot[] = [];
  
  // 兜底品先占位
  if (cfg.freeTierAlwaysShow) {
    for (const tierId of cfg.freeTierAlwaysShow) {
      if (slots.length < cfg.slots && pool.includes(tierId)) {
        slots.push(makeSlot(tierId));
      }
    }
  }
  
  // 剩下的槽位加权随机
  const remaining = pool.filter(id => !slots.find(s => s.itemId === id));
  while (slots.length < cfg.slots && remaining.length > 0) {
    const picked = weightedRandomPick(remaining);
    slots.push(makeSlot(picked));
    remaining.splice(remaining.indexOf(picked), 1);
  }
  
  // 价格波动
  for (const s of slots) {
    s.price = applyPriceVariance(s.basePrice);
  }
  
  return slots;
}
```

### 10.2 货架数据持久化

货架内容随存档保存：
- 玩家退出游戏 → 重新进 → 看到的还是上次留下的货架
- 货架重置只在 §2.1 的触发时机发生
- 同 seed / 不同存档不影响（货架是玩家个人数据）

### 10.3 货架的"过期感"

如果玩家**长时间不下潜也不买**（比如停留岸上 5 分钟以上），货架自动加一句话术："老板正在打盹"，物品全部稍微变暗（视觉提示"该出门了"）。

## 十一、与其他系统的边界

- 与背包：商店里的物品**不直接进背包**。永久装备直接装备，消耗品/应急品入"消耗品库存"，下次进出发准备页时装载。
- 与图鉴：商店里**不出现古物**（古物只能下潜捡）。这个边界要严格守住。
- 与救援：救援成功的"额外货架"（rescueBonusShelf）只在该次下潜回岸时出现一次，进了一次商店后即消失。
