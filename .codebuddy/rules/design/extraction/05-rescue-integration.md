# 05 — 救援任务与撤离玩法的穿插

> **本卷优先级：🟡 中**
> 本案的灵魂之一：让"赚钱"和"救人"同时存在但不互相侵蚀。
> 顶层设计原则 → [../09-extraction-loop-design.md](../09-extraction-loop-design.md)

---

## 一、设计核心

### 1.1 救援与经济**分轨**，但**共享场地**

- 经济玩法每次下潜都在跑（捡东西、撤离、卖货）
- 救援任务**偶发触发**，叠加在经济玩法之上，不替代经济玩法
- 救援的奖励是**名声 + 装备图纸**，**不直接给金币奖励**（但有"保险金"补偿装备成本）

### 1.2 救援不是 KPI

- 玩家可以**随时拒绝**救援
- 拒绝**不掉名声**
- 失败**不掉名声**
- 救援只是"良心驱动的支线"，不是"必须完成的日常任务"

### 1.3 与现有系统的关系

完整复用项目已实现的：
- 警情通报全屏页（briefing）
- 案件结案叙事页（resolved / abandoned）
- NPC 救援机制（绑绳柔性跟随）
- 案件编号 / 伪 GPS 坐标 / 接警时间叙事包装

本卷只在这些之上**叠加经济结算**，不重做。

## 二、触发机制

### 2.1 触发概率

每次玩家从 menu 进入迷宫模式（或点"接受新任务"），按概率 roll 是否有警情通报：

| 玩家段位 | 警情触发概率 |
|---|---|
| 首次进入迷宫模式 | **100%**（新手必触发） |
| 累计下潜 < 5 次 | 50% |
| 累计下潜 5~15 次 | 30% |
| 累计下潜 > 15 次 | 20% |
| 上次下潜是救援成功 | -10%（让玩家喘口气） |
| 累计连续拒绝 ≥ 3 次 | +20%（系统更着急） |
| 累计连续拒绝 ≥ 5 次 | 触发特殊叙事彩蛋（见 §5） |

> 这套概率让"老玩家"主要在做经济玩法，但**偶尔被拉回救援的初心**。

### 2.2 触发时机

警情通报 overlay 在玩家**回到岸上**的瞬间显示（不是下潜中）。
之前已经是"接受新任务 → 警情通报 → 下潜"，本卷只是把"接受新任务"按钮改为"按概率 roll"。

### 2.3 警情通报页改动

现有警情通报页底部按钮改造：

```
现有：
  [ 接受任务 ▶ ]

改为：
  [ 接受任务 ▶ ]   ← 主操作（绿色）
  [ 今天太累了 ]   ← 次操作（灰色，新增）
```

**"今天太累了"行为**：
- 关闭警情通报页
- 进入普通搜刮下潜
- 岸上界面有一行小字："你看着对讲机，没有按下接听键。"
- 不掉名声、不影响后续触发概率

## 三、救援任务下潜的玩法变化

### 3.1 玩法叠加（不替代）

接受救援任务后，本次下潜：

- ✅ **仍可拾取战利品**（背包系统正常工作）
- ✅ **仍可发现图鉴**（手电照到正常解锁）
- ➕ **新增任务目标**：找到 NPC + 绑绳 + 带回水面（沿用现有 NPC 救援逻辑）
- ➕ **救援奖励**叠加在经济结算之上

### 3.2 任务目标的 UI 提示

下潜中 HUD 新增一条任务条幅（顶部偏下，避免与现有左上 HUD 冲突）：

```
任务：营救张木林（卡在 -34m 深处）
状态：未发现 / 已发现 / 已绑绳
```

NPC 状态由现有 `state.npc.state` 派生，不新增字段。

### 3.3 救援与经济的取舍

玩家在下潜中要做的取舍：

- **"先救人还是先搜刮？"**：如果时间紧迫（氧气剩 50%），是直接去救人，还是再去捡两个稀有物？
- **"绑绳后还要不要绕路捡东西？"**：绑了 NPC 后回程会被拖慢，但路上有未捡的史诗物
- **"NPC 死了还要不要继续捡？"**：救援已失败，但本次仍可继续搜刮，反正背包里东西还能带回

这种取舍是叙事和玩法张力的来源——不要消除它。

## 四、救援结算

### 4.1 救援成功

NPC 被成功带回水面 → 触发现有"案件结案 · 成功营救"叙事页 + 经济结算页。

经济结算追加：

```
──── 救援报告 ────
营救成功 ✓

奖励：
  +50 名声
  +200 金币（救援保险金，由调度中心支付）
  装备图纸概率掉落... 

[ 1/3 概率掉落 ]
★ 解锁装备图纸：专业救援者背包 16 格 ★
```

### 4.2 救援失败（玩家活但 NPC 死）

继续完成下潜并撤离 → 结算页显示：

```
──── 救援报告 ────
营救失败 ✗
"你已经尽力了。"

无奖励，无惩罚。
```

经济结算正常（捡到的东西照样卖钱）。
不掉名声、不掉金币、不影响下次触发。

### 4.3 玩家死亡（带救援任务）

死亡撤离 → 显示现有失败页 + 一行：

```
──── 救援报告 ────
玩家与被困者一同失踪。
两人被记入"未结案"档案。
（不损失名声，不影响下次触发）
```

### 4.4 装备图纸掉落

救援成功时，按以下概率掉装备图纸：

| 名声段位 | 图纸掉落率 |
|---|---|
| 0~99 | 30% |
| 100~299 | 25% |
| 300~599 | 20% |
| 600+ | 15%（已经接近全开） |

掉落的图纸**随机从未解锁池**抽：

| 图纸 | 解锁的装备 | 制作成本 |
|---|---|---|
| 专业救援者背包 | 16 格背包 + 内置 1 救生信标 | 1500 金 |
| 双层防水背包 | 12 格背包，半成功撤离丢失率 50% → 25% | 800 金 |
| 救援者氧气瓶 | 大氧气瓶级别 + 紧急时回 20% | 200 金（消耗品） |
| 加固脚蹼 | 速度 1.1× + 撞岩耗氧 ×0.7 | 600 金 |
| 调度中心信标 | 救生信标 + 不消耗（多次使用） | 800 金 |
| 反光手电 | 手电距离 ×1.5 | 400 金（消耗品） |

图纸**可以在商店"图纸合成"区**用金币 + 图纸合成专属装备。
图纸首版可不做"合成"，先做"图纸即装备"（救援送的就是装备本身）。

## 五、连续拒绝的彩蛋

### 5.1 触发条件

玩家在 5 次连续可触发救援的下潜中都选择"今天太累了" / 玩了普通模式。

### 5.2 表现

下次进入岸上时：

- 警情通报照常 roll，但**强制触发**一次
- 通报内容**不一样**：

```
紧急通报 EMERGENCY

来自：调度中心 - 王主任
时间：07:28

"对讲机里你最近接听的频率太低了。
我知道你也累。
但今天这个孩子没人能去——他卡在 -45 深处，
我们已经联系了三个城市的救援队。

哪怕你只是去看一眼也好。"

[ 我去 ]                    [ 真的不行了 ]
```

### 5.3 选择影响

- 选"我去"：本次救援成功的奖励 ×2（保险金 400 + 名声 100）
- 选"真的不行了"：触发额外叙事，对讲机彻底沉默 5 次下潜（这期间没有警情通报）

### 5.4 设计意图

这是**叙事彩蛋**，不是惩罚。让玩家"长期专注经济玩法"也有戏剧性结果——你的"累"被系统看见了。
此机制每个存档**只触发一次**，避免重复。

## 六、名声系统

### 6.1 名声的获取

| 行为 | 名声 |
|---|---|
| 每次救援成功 | +50 |
| 王主任彩蛋的"我去" | +100 |
| 救援失败 / 拒绝 / 玩家死亡 | 不变 |

### 6.2 名声的消耗

名声**不消耗**，只递增。它是"档案上的记录"。

### 6.3 名声段位的解锁内容

| 段位 | 名称 | 解锁内容 |
|---|---|---|
| 0~99 | 调度中心实习生 | 起步装备 + 商店基础物品 |
| 100~299 | 持证救援员 | 商店上架"二手装备"（折价款） |
| 300~599 | 资深救援员 | 商店上架"图纸合成"功能 |
| 600~999 | 区域调度长 | 解锁"夜间救援任务"（更难，奖励翻倍） |
| 1000+ | 雅各布井档案官 | 主线相关救援剧情解锁 + 特殊称号 |

### 6.4 段位提升的视觉反馈

跨段时，岸上有一段简短动画：
- 一封手写信掉落 / 一张证书贴上墙
- 写着 "调度中心：恭喜晋升..."
- 没有 BGM 高潮，保持克制叙事感

## 七、夜间救援任务（名声 600+）

### 7.1 解锁条件

名声 ≥ 600 后，警情通报偶尔会**升级为"夜间救援"**。

### 7.2 玩法变化

| 项 | 普通救援 | 夜间救援 |
|---|---|---|
| 视觉 | 正常 | **整张地图调暗 30%**，手电照射距离收窄 ×0.7 |
| 食人鱼 | 正常 | 攻击性 ×1.5，数量 +1 群 |
| 氧气消耗 | 正常 | ×1.2 |
| 救援奖励 | +50 名声 | +120 名声 |
| 保险金 | +200 | +500 |
| 战利品 | 正常 | 场景多刷 5 件物品（夜间老人下潜的遗物） |

### 7.3 触发方式

警情通报页加一个红色徽章：

```
紧急通报 EMERGENCY ⚠ 夜间救援

注意事项：
- 视野受限
- 食人鱼活性增加
- 氧气消耗加快

[ 我去 ]   [ 今天不行 ]
```

夜间救援拒绝的概率比普通救援高一点，是常态。

## 八、与主线叙事的对接（远期）

`08-toner-master-narrative.md` 描述了项目主线的"完美结局所需的特定 NPC"。

名声 1000+ 后，警情通报池里**插入主线 NPC**：

- 名声 1000 → 解锁"小潘的妹妹"救援
- 名声 1500 → 解锁"熊子的搭档"救援
- 名声 2000 → 解锁主线女孩支线

这些救援不是"普通救援"——成功后会触发独立的叙事页和长文回忆，是**完美结局的隐藏条件**。
玩家如果只玩经济不做救援，永远见不到这些剧情。

> 这是经济玩法和叙事玩法的最深层耦合：**钱多不一定能见到完美结局，要靠"良心"**。

## 九、待确认问题

1. **名声系统是否首版必做**？
   - 不做的话救援只有"金币奖励 + 装备解锁"
   - 做的话长期玩家有"被认可"的成就感
   - 我倾向第一阶段不做，第二阶段加
2. **装备图纸是否要做合成系统**？
   - 简化方案：图纸 = 装备直给（救援掉的图纸立刻变装备）
   - 复杂方案：图纸 + 金币 → 合成
   - 第一阶段建议简化
3. **夜间救援是否过于复杂**？
   - 可以推到第二阶段
   - 但"普通救援 vs 夜间救援"的差异化是叙事差异化的好抓手
4. **彩蛋"王主任"的"5 次拒绝"次数是否合理**？
   - 太少 → 玩家就不想拒绝了
   - 太多 → 玩家忘了这个彩蛋存在
5. **保险金 200 金是否合理**？
   - 数值偏低 → 玩家觉得"救援不划算"
   - 数值偏高 → 经济会通胀
   - 建议小步调
6. **救援失败的代价是否要做**？
   - 当前是"零代价"
   - 是否要做"救援失败时丢失部分名声" → 但这违反"救援不是 KPI"原则
   - 我倾向不做

## 十、与现有系统的隔离

- 沿用现有警情通报页 / 结案页 / NPC 救援逻辑
- 救援触发概率独立模块 `RescueChance.ts`
- 名声数据进 `state.extraction.reputation`
- 图纸数据进 `state.extraction.unlockedSchematics: string[]`
- 王主任彩蛋是一次性事件，标志位进 `state.extraction.flags.wangMasterTriggered`

详见 [07-engineering-isolation.md](./07-engineering-isolation.md)。
