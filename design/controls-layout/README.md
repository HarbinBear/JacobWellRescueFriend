# 横竖屏切换与双手操作

本轮直接接入实际小游戏，不替换随身听、齿轮、手电、氧气环的原生图形。

- 竖屏保持贴左边缘向下排列，横屏使用贴顶横排；两个方向分别布局。
- 横竖屏按钮独立可见，显示将切换到的屏幕方向。微信右上角胶囊附近不放工具。
- 顶部只保留设备报告的实际安全区和 8px 间距，去掉固定 62px 顶部占位。
- 体力固定在左上短条：竖屏 44px、横屏 60px。左手移动区在按住时也不显示摇杆。
- 右侧只保留绳索与交互两个常态入口，约 52px；按住展开 136px 选向盘。敲晕、拆绳和解扣仍共用交互入口，由目标决定行为。
- BCD 在竖屏右侧竖排，在横屏右手区上方横排；充排气逻辑不变。

切屏使用 `wx.setDeviceOrientation`（最低基础库 2.26.0），由窗口事件同步逻辑尺寸、DPR、主画布和两张光照画布。方向偏好单独保存为 `jwr-screen-orientation`；保持默认竖屏配置，不重开当前案件、不写入玩法存档。切屏及后台中断会结束输入和未完成动作，防止旧坐标继续游动、操作或充排气。

## 本地预览与检查

执行 `npm run controls:preview`，通过工作区静态服务打开 `node_modules/.cache/controls-layout/game.html`。页面运行实际游戏代码；左上角直接切屏，主菜单可进入岩体试跑。全部生成物、截图和报告均在 Git 忽略的缓存目录。

`npm run controls:check` 覆盖窗口/安全区、原生请求失败与超时、偏好恢复和按钮边界；`npm run controls:browser` 使用独立无头 Chrome 的原生多点触控检查双手预选、持有 BCD 时切屏、输入释放、画布光照、背包、主菜单和玩法存档保持。可用 `JWR_PREVIEW_URL` 覆盖默认本地地址。

浏览器适配层模拟微信方向接口。微信开发者工具和手机上的系统安全区、原生转屏动画与手感仍需真机验收。
