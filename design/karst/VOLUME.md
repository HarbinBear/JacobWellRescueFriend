# 三维洞腔接入手机版：v1.0.24

新章节的水下溶洞默认改为三维洞腔（`CONFIG.karst.geometryMode = 'volume'`）。玩法仍是二维，只把岩石这一层换成带透视的三维网格。目前有程序层理与细尺度法线，还没有完整的岩石材质。旧版平面岩壁（`legacy`、`chambers`）保留，可在 GM「溶洞 / 造型」里切回，只对新章节生效。

## 做法

- 约束来自游戏的种子迷宫：每个开放格是一段必须走得通的路。格子越靠大厅中间，洞越宽、往里越深；洞顶洞底整体长出钟乳石；另有从洞的深处拐进岩石里的支洞，进不去，只提供纵深（`src/world/KarstVolume.ts`）。
- 后壁按迷宫区域选用三类规则：浅流石褶皱、错层岩台、深裂隙。相邻区域连续混合，既有能承接回光的浅壁，也有暗下去的深槽；只修改 z>100 的后方形状。默认种子分别有 10、21、11 个区域，规则与参数均由种子确定。
- 碰撞用的二维密度场是洞腔在游戏平面（z=0）上的切面，写进原来的 `KarstTerrain.field`。碰撞、手电遮挡、绳索找墙、鱼的近障判定和锚点查询都沿用原有代码，不分两套轮廓。
- 每个开放格都保证按身体半径游得到：被堵住的格子会从迷宫里的上一格开一条刚好过人的路。游戏平面上和入口完全不连通的水域一律填成岩石；和通路连着但太窄的缝隙会保留。
- 整张地图只计算 z=0 一层。带纵深的网格分块生成（每块 48×48 格、21 层），拆成小步，以每帧约 6 毫秒为目标。完整纵深视锥内的块优先，其次是手电范围内的屏外阴影块，再按约一秒的移动预测和静止转向余量预热。常驻目标 40 块；必要可见/阴影块超过目标时优先保证完整性，不强行裁掉。离开的旧块释放（`src/render/RenderKarstVolume.ts`、`KarstVolumeStreaming.ts`）。
- 相机的消失点在屏幕正中，游戏平面与二维镜头逐像素对齐，潜水员、鱼、绳索的绘制不变。洞壁画在它们后面。
- 手电沿用 S03 小样的三维光锥，把明亮的中心光斑和宽柔光叠起来。7 条平面射线和 3 条斜向后壁的射线查找落点，近处反照与落点汇总的回光共同给洞顶、侧壁和前方铺上一层幽蓝。落点查询覆盖全地图，不以是否出现在镜头里为条件。阴影另用手电范围内的网格，屏外岩壁也会遮光。角色身后回光弱，最深处仍沉进黑暗。
- 原有遮罩负责人物、鱼和绳索。洞室里的水中光柱在暗罩之后以屏幕混合恢复，即使没有命中岩石也有清晰的蓝色方向感。三维洞壁亮度在遮罩之后恢复，另留少量回光散射，避免重叠成一层过亮的蓝雾。
- 岩面使用世界坐标连续的层理与两档颗粒噪声扰动法线和底色，不增加纹理贴图；这是补充表面起伏，不能代替真实断层、破碎岩块和矿物材质。
- 存档记住洞形。缺少该字段的旧存档继续用旧洞形，不会把角色卡进新洞壁里。

## 查看与检查

- `npm run shaders && npm run karst:preview` 后从本地静态服务打开 `node_modules/.cache/karst-review/live/game.html`。默认进入三维洞腔，加 `?legacy` 进入旧版。右侧按钮可跳到大厅、窄道、井底和三类后壁，也可转灯或切换灰模。
- `npm run world:preview` 是不带评审按钮的手机版主流程。
- `JWR_KARST_GENERATION=volume node scripts/checkKarstTerrain.js`：5 个种子的通路、真实半径导航、碰撞与射线一致、同种子结果一致。
- `npm run karst:volume` 先检查分块需求的预测、屏外阴影、远镜头覆盖与边界，再检查网页版的生成、游动、续档、图形上下文恢复，以及第二个大厅同一机位的回光、转灯和关灯。关闭回光时仍检查光柱亮度。截图在 `node_modules/.cache/karst-review/volume/`。
- 后壁改动另对 5 个种子的完整 Float32 碰撞场与改动前版本逐字节比对，一致。桌面横竖屏与一段 10 秒实际游动也另行检查：601 帧，移动约 1521 世界单位，镜头内缺块为 0 帧，稳定后有 6 个屏外阴影块。这不能代替不同设备和更长路线的验收。
- 2026-11-11 本轮通过 `typecheck`、`karst:volume`、`world:regression`、`rope:check` 和包体检查。静态估算 8,154,441 字节，距 8 MiB 上限余 234,167 字节；这不是微信工具编译后的官方大小。
- 初次接入时，原有 `world:entry`、`world:stability` 在新默认下通过；`karst:browser`、`checkKarstVariants.js`、`checkKarstSaveVariants.js` 改走 `?legacy` 入口后通过。这些未在本轮全部重跑。

## 已知不足

- 只在桌面 Chrome 无头模式跑过。微信真机上的着色器兼容、帧率、显存和编译后包体都没有测。
- 阴影现在会额外绘制屏外岩壁，且程序法线增加片元开销。6 毫秒是生成预算目标，并非单步耗时上限；手机上的帧率和显存仍是未知数。
- 后壁仍是一个深度场，尚不能表达相互遮挡的多层岩架。已有分区与法线细节，但整体仍偏柔软，真实岩石结构和材质尚未完成。
- 深裂隙评审机位下方可见局部细小黑缝，网格/钟乳石边界的原因尚未确定，已记入待办。
- 回光是落点估算，并非真实全局光照。后壁落点用深度场求交，前景按平面轮廓阻挡，中间三维钟乳石的二次遮挡仍是近似。水里散射与前景遮罩也仍按屏幕和游戏平面近似。
- 预加载解决了已检查路线的游动补块；传送、首次进入和上下文恢复仍要重新生成，低性能手机或极端镜头可能追不上。
- 潜水员和鱼仍是二维绘制，与洞室的受光、遮挡并未统一。下一步先以一条三维鱼验证共同的灯光与深度，再改潜水员和绳索；具体顺序记录在 `ToDo.md`。
- 井口处岸坡还是原来的图片，往下过渡到三维洞壁，衔接不自然。岸上部分没有改。
