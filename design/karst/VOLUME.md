# 三维洞腔接入手机版：v1.0.24

新章节的水下溶洞默认改为三维洞腔（`CONFIG.karst.geometryMode = 'volume'`）。玩法仍是二维，只把岩石这一层换成带透视的三维网格。目前是灰模，没有矿物材质。旧版平面岩壁（`legacy`、`chambers`）保留，可在 GM「溶洞 / 造型」里切回，只对新章节生效。

## 做法

- 约束来自游戏的种子迷宫：每个开放格是一段必须走得通的路。格子越靠大厅中间，洞越宽、往里越深；洞顶洞底整体长出钟乳石；另有从洞的深处拐进岩石里的支洞，进不去，只提供纵深（`src/world/KarstVolume.ts`）。
- 碰撞用的二维密度场是洞腔在游戏平面（z=0）上的切面，写进原来的 `KarstTerrain.field`。碰撞、手电遮挡、绳索找墙、鱼的近障判定和锚点查询都沿用原有代码，不分两套轮廓。
- 每个开放格都保证按身体半径游得到：被堵住的格子会从迷宫里的上一格开一条刚好过人的路。游戏平面上和入口完全不连通的水域一律填成岩石；和通路连着但太窄的缝隙会保留。
- 整张地图只计算 z=0 一层。带纵深的网格按镜头附近分块生成（每块 48×48 格、21 层），拆成小步，每帧只算约 6 毫秒；离开很远的块会释放（`src/render/RenderKarstVolume.ts`）。
- 相机的消失点在屏幕正中，游戏平面与二维镜头逐像素对齐，潜水员、鱼、绳索的绘制不变。洞壁画在它们后面。
- 光锥按游戏平面上的方向判断，所以照亮的范围和二维光锥一致；明暗按三维距离、朝向和阴影算，越往里越暗，最深处沉进黑暗。
- 游戏原有的黑暗遮罩会把洞壁再压暗一次，所以遮罩之后把被压掉的洞壁亮度加回去；人物、鱼和绳索仍被遮罩压暗。
- 存档记住洞形。缺少该字段的旧存档继续用旧洞形，不会把角色卡进新洞壁里。

## 查看与检查

- `npm run karst:preview` 后打开 `node_modules/.cache/karst-review/live/game.html`，默认进入三维洞腔；加 `?legacy` 进入旧版。右侧按钮可跳到大厅、窄道、井底，切换灰模。
- `npm run world:preview` 是不带评审按钮的手机版主流程。
- `JWR_KARST_GENERATION=volume node scripts/checkKarstTerrain.js`：5 个种子的通路、真实半径导航、碰撞与射线一致、同种子结果一致。
- `npm run karst:volume`：实机网页里的生成、绘制、游动、续档和图形上下文恢复。截图在 `node_modules/.cache/karst-review/volume/`。
- 原有的 `world:entry`、`world:stability`、`world:regression`、`rope:check` 在新默认下通过；`karst:browser`、`checkKarstVariants.js`、`checkKarstSaveVariants.js` 改走 `?legacy` 入口后通过。

## 已知不足

- 只在桌面 Chrome 无头模式跑过。微信真机上的着色器兼容、帧率、显存和编译后包体都没有测。
- 画面内约 13 万三角面，带阴影时每帧画两遍。分块生成在桌面上单步最长约 7 到 10 毫秒，手机上会更慢，游动时可能掉帧。
- 没有材质，洞壁是单一的青灰色，表面偏光滑。
- 最大的厅里手电可能照不到任何洞壁，画面大半是黑的。
- 光束打到洞壁后的反照只是一盏没有遮挡的补光；水里的光束和黑暗遮罩仍按二维轮廓算。
- 井口处岸坡还是原来的图片，往下过渡到三维洞壁，衔接不自然。岸上部分没有改。
