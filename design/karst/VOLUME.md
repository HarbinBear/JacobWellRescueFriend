# 三维洞腔接入手机版：v1.0.24

新章节的水下溶洞默认使用三维洞腔（`CONFIG.karst.geometryMode = 'volume'`）。玩法仍是二维。目前仅保留浅层缘、细颗粒与稀疏低对比色差；大尺度软性法线和矿物覆盖已因观感退步撤回。旧版平面岩壁（`legacy`、`chambers`）保留，可在 GM「溶洞 / 造型」里切回，只对新章节生效。

## 可见度与色彩的当前取舍

角色保留美术补光：30 单位内的局部全向亮度为 0.60，至 90 单位平滑归零，关灯仍保留。上一版给整室岩面加环境底光的做法已被用户否定，不能再把“全室都读得出”作为验收标准。亮处明确、回光渐弱、未照到的区域留黑；深处和背后应保留不可见空间。

三维手电光轴向洞内倾斜 18°，XY 投影仍沿角色朝向，光锥维持 65°。直接照明、阴影相机和三维落点采样使用同一个光轴，因此空旷时可扫到部分纵深岩面，随后产生真实落点回光，而不是给全部后壁补一层亮度。射程内没有岩面时允许只剩光柱及角色；不能为了填满画面凭空照亮岩壁。

`CONFIG.karst.volumeVisibility=1` 现在仅控制锥内弱水中回散：与直接光共用光锥、射程和阴影，关灯归零、锥外归零。这仍是美术近似，没有求解水体多次散射。岩面恢复以真实网格法线为主，撤掉大尺度颗粒鼓包和沉积覆盖造成的软化，只留浅层缘、细粒及 `volumeMaterial` 控制的稀疏低对比暖色。近灯略偏青灰，远处与回光保持幽蓝。本轮没有修改洞形和碰撞；材质不视为已完成。

当前只验证一处洞顶自然沉积，先看灰模与实际游动。S03只记录此前纠偏过程，不再作为当前造型标杆；按自然生长形态与实际构图判断，不能靠表面噪声代替几何。鱼、绳索与潜水员的共同深度和受光仍排在后续，不混入这次灯光纠偏。

## 2026-11-12 洞顶沉积小样

本轮先做的规则岩台和切口被用户明确否定，相关生成代码已全部撤掉。洞腔主体保持 c8049bd 的造型与灯光，只在入口附近的一处洞室试做依附洞顶的自然沉积。此处不以S03为标杆，按自然沉积形态与实际观感判断。

`KarstSpeleothems.ts` 给出水平 x/z 上连续的沉积长度，挂根仍由 `KarstVolume.ts` 实际洞顶扫描决定。三组钟乳石的宽根、长度和纵深位置不同，向细尖收束；一段石幔沿纵深弯曲，厚度与底缘连续变化。局部减弱原有碎小沉积，让主体稍清楚；洞室、后方支洞、洞底和灯光都不重塑。新增生长仍限制在原300单位长度上限内，避免超出分块洞顶扫描余量。

样例只在 `64<z<420`、入口拼接线下方及所选洞室附近渐入；z=0碰撞场不变。其密度场、三角网格、阴影与回光查询同源。原有网格采样限制仍在，薄褶皱和尖端尚不够细，本轮只保留小范围样例，不视为岩石美术已经完成。

评审页加 `?speleothems` 直接进入样例，“沉积样例 / 原洞形对照”保留角色位置、只重建显示分块。临时截图和检查报告留在忽略缓存。5个种子的完整碰撞场与c8049bd逐字节一致；默认种子样例及外围16块网格通过有限值、索引与零丢面检查，改动域共享探针一致。默认种子覆盖区共153,900三角（包含外围，并非全部同时绘制），整块同步生成中位73毫秒，不代表单帧耗时。10秒录制（4秒转灯、6秒自动游动）记录601帧，移动约397单位，可见缺块与穿墙均为0，桌面生成单步最长12毫秒；不代表微信真机性能。类型、`karst:volume`、`world:regression`和包体检查通过。静态估算8,166,819字节，余量221,789字节，不是微信工具官方大小。先前检查也发现旧版seed7391在z16/32有包含跨零面的块间差异，已记录到ToDo；不能据局部检查宣称全图接缝已解决。

## 2026-11-11 造型纠偏依据

上一轮将洞腔与 `rearDepth(x,y)-z` 相交，直接截掉了后方支洞与遮叠关系。这不是“复杂洞腔”，不能继续用表面法线掩盖。S03 原小样位于 `design/cave-volume`，第三版提交为 `f238e21`。当前先恢复它的自然收束和立体沉积关系，再决定材质，不为均匀照明改变洞形。

参考资料与造型规则：

- [英国地质调查局：洞穴如何形成](https://www2.bgs.ac.uk/mendips/caveskarst/caveform.htm)：层面与节理控制通道的走向和比例，水下通道可呈回环。对应生成时的区域轴向、深宽比与弯曲，不能所有区域都沿屏幕法向挤出。
- [美国国家公园局：洞穴地质细节](https://www.nps.gov/grba/planyourvisit/cave-geology-in-depth.htm)：石钟乳、石笋、石幔和流石与滴水、斜壁流水等沉积条件有关。对应依附洞顶/洞底、方向明确的成组沉积；当前水下的石钟乳可表现曾经出露、后来淹没的遗存，不把所有水下岩面都当作正在滴水生长。
- [美国国家公园局：Lehman 洞穴成因的新证据](https://www.nps.gov/grba/learn/nature/lehman-caves-origin.htm)：不同溶蚀机制可能产生沟槽、溶蚀凹槽与悬挑，不是同一种噪声的振幅变化。本游戏只借鉴这些形态关系，不声称复原该洞穴的地质历史，也不把其特殊硫酸成因套到全部洞室。

验收先看实际网格的侧向收束、遮叠、顶底沉积和支洞，不以法线纹理或灯光遮住形体缺陷。灰模检查应使用几何法线。

## 平面交互与三维表现的边界

当前 `RopeNet` 的结点、线交成结和扫掠碰撞都只有 x/y，`FishEnemy` 的移动与避障也没有 z；洞壁先画，鱼/绳/潜水员随后走 Canvas 2D。贴纸感既来自分离的绘制管线，也来自真实的平面玩法限制。

当前选择先验证明确的 2.5D 剖面玩法：鱼体和绳段可做有厚度的网格，与洞壁共用相机、灯光、深度；它们的交互中心和结点仍在操作平面。先验证一条鱼与两根绳的真实碰撞、缠住与拆绳，不能以静态截图代替可玩验收。深处空间暂是环境，不能宣称角色可自由进入全部纵深。

若这一限制仍不能接受，第二步才是有厚度的交互带：对象保存真实 z，只有在相同深度范围才相撞；绳结需三维接近，远处鱼可绕过近处网。鱼进入交互带必须连续运动并避开实际三维岩壁，不可突然吸回平面。这会改变“网封路”的规则、锚点、选取和存档，需要作为玩法修改验收。完整自由三维还要重做镜头与移动输入，不能归入一次美术替换。

## 做法

- 约束来自游戏的种子迷宫：每个开放格是一段必须走得通的路。格子越靠大厅中间，洞越宽、往里越深；洞顶洞底整体长出钟乳石；另有从洞的深处拐进岩石里的支洞，进不去，只提供纵深（`src/world/KarstVolume.ts`）。
- 深处形状按区域控制完整洞腔的轴向、深宽比、弯曲和沉积强度：流蚀管道、沉积洞室、宽拱厅和倾斜裂隙。靠近操作平面保留旧形，向内逐渐转为自然收束的体积；后方支洞接在主洞收束之前。没有统一的浅背板。沉积净空按三维距离计算，不再把整条通路沿纵深清空。
- 碰撞用的二维密度场是洞腔在游戏平面（z=0）上的切面，写进原来的 `KarstTerrain.field`。碰撞、手电遮挡、绳索找墙、鱼的近障判定和锚点查询都沿用原有代码，不分两套轮廓。
- 每个开放格都保证按身体半径游得到：被堵住的格子会从迷宫里的上一格开一条刚好过人的路。游戏平面上和入口完全不连通的水域一律填成岩石；和通路连着但太窄的缝隙会保留。
- 整张地图只计算 z=0 一层。带纵深的网格分块生成（每块 48×48 格），拆成小步，以每帧约 6 毫秒为目标。完整纵深视锥内的块优先，其次是手电范围内的屏外岩壁，再按约一秒的移动预测和静止转向余量预热。常驻目标 40 块；必要可见/光照块超过目标时优先保证完整性，不强行裁掉。离开的旧块释放（`src/render/RenderKarstVolume.ts`、`KarstVolumeStreaming.ts`）。
- 纵深共 31 个采样层，前 400 深度每 16 单位一层，最远处降低密度。为包含最大沉积长度，块外扫描余量增至上 32、下 20 格；石笋强度不再依赖该块是否扫描到了洞顶。两处洞室的相邻块检查中，零面附近的不一致已消除。
- 相机的消失点在屏幕正中，游戏平面与二维镜头逐像素对齐，潜水员、鱼、绳索的绘制不变。洞壁画在它们后面。
- 三维主动光锥与二维水中光柱共用 `CONFIG.fov`（默认 65°），三维光轴朝洞内倾斜 18°，不再有约 150° 的额外宽光锥。10 条锥内射线查询与网格同源的三维密度场，只取首个岩面；没有命中或经过尚未加载区域时不生成回光。实际命中点按入射角、距离、灯光能量向岩面朝水的半球反射，散布半径 650。屏外岩壁在光照范围内也会被查询和投影。删除了玩家中心的 `nearGlow`、全室 `room` 补光及跟随蓝雾。
- 原有遮罩负责人物、鱼和绳索；在三维模式中读取同一组岩面回光，并保留上述角色局部补光。洞室里的水中光柱仍在暗罩之后恢复，即使没有命中岩石也能看见方向。三维洞壁亮度在暗罩之后恢复。前景仍未共享三维深度缓冲。
- 光照采样保留已生成分块的 Int8 密度场，不再次生成整张三维地图。射线按 12 单位前进、命中后细分；场分辨率、量化和薄刃会影响精度，它不是逐三角形路径追踪。
- 岩面使用世界坐标连续的浅层缘、细颗粒及稀疏色差，不增加纹理贴图；这不能代替真实断层、破碎岩块与完整矿物细节。
- 存档记住洞形。缺少该字段的旧存档继续用旧洞形，不会把角色卡进新洞壁里。

## 查看与检查

- `npm run shaders && npm run karst:preview` 后从本地静态服务打开 `node_modules/.cache/karst-review/live/game.html`。默认进入三维洞腔，加 `?legacy` 进入旧版。右侧按钮可跳到大厅、窄道、井底和不同造型区域，也可转灯或切换几何灰模。
- `npm run world:preview` 是不带评审按钮的手机版主流程。
- `JWR_KARST_GENERATION=volume node scripts/checkKarstTerrain.js`：5 个种子的通路、真实半径导航、碰撞与射线一致、同种子结果一致。
- `npm run karst:volume` 先检查分块预测、屏外阴影、远镜头覆盖与边界，以及三维射线的首个落点、未知块、法线方向、射程等，再检查网页版生成、游动、续档、图形上下文恢复和开关灯。关闭回光时仍检查光柱。截图在 `node_modules/.cache/karst-review/volume/`。
- 前轮造型纠偏对 5 个种子的完整 Float32 碰撞场与改动前版本逐字节比对，一致。桌面横竖屏与 10 秒实际游动复测：601 帧，移动约 1521 世界单位，镜头内缺块为 0 帧，稳定后有 6 个屏外阴影块。缓存共 32 块、约 31.5 万三角面（并非全部同时在画面内），密度场占约 2.45 MiB，生成单步最长 12 毫秒。这不能代替不同设备和更长路线的验收。
- 2026-11-11 造型纠偏通过 `typecheck`、`karst:volume`、`world:regression`、`rope:check` 和包体检查。静态估算 8,162,471 字节，距 8 MiB 上限余 226,137 字节；这不是微信工具编译后的官方大小。
- 前一版光照材质虽通过功能检查，但用户否定了全室过亮和泥浆般表面。旧的“光柱外必须增亮”断言保护了错误行为，已改为锥外不可被回散抬亮、关灯不可残留回散，同时保留角色可见度、光柱与真实回光检查。功能通过不代表美术通过。
- 当前暗部纠偏通过 `typecheck`、`karst:volume`、`world:regression`、包体检查。关闭真实回光后，切换锥内回散时背后采样亮度保持 5.75（0–255）；关灯后的前后区域变化小于 0.04，角色区域约 40.3。游动、续档、上下文恢复通过。静态包体 8,163,967 字节，余量 224,641 字节；不是微信官方编译大小。
- 初次接入时，原有 `world:entry`、`world:stability` 在新默认下通过；`karst:browser`、`checkKarstVariants.js`、`checkKarstSaveVariants.js` 改走 `?legacy` 入口后通过。这些未在当前光照材质轮全部重跑。

## 已知不足

- 只在桌面 Chrome 无头模式跑过。微信真机上的着色器兼容、帧率、显存和编译后包体都没有测。
- 阴影现在会额外绘制屏外岩壁，且程序法线增加片元开销。6 毫秒是生成预算目标，并非单步耗时上限；手机上的帧率和显存仍是未知数。
- 前轮恢复完整体积，矿物材质样例已撤回；尚未完成精细岩层、破碎块体和完整矿物材质；也不等于真实溶蚀模拟。结构仍需主观美术验收。
- 前轮修复了沉积扫描造成的块间不一致，并减轻稀疏纵深采样造成的锯齿；薄边、近处转折和其他种子的局部网格仍需继续检查。
- 回光从实际三维岩面命中点出发，但落点至接收面的第二段遮挡仍以半球近似，可能漏过中间岩体；没有多次反弹求解。水中光柱仍按二维切面遮挡，不能声称全部光学过程已统一。
- 预加载解决了已检查路线的游动补块；传送、首次进入和上下文恢复仍要重新生成，低性能手机或极端镜头可能追不上。
- 潜水员和鱼仍是二维绘制，与洞室的受光、遮挡并未统一。洞室形体样例之后，以一条三维鱼验证共同的灯光与深度，再改潜水员和绳索；具体顺序记录在 `ToDo.md`。
- 井口处岸坡还是原来的图片，往下过渡到三维洞壁，衔接不自然。岸上部分没有改。
