## 实际卡点

- `FishVolumeMesh.ts`的循环尾摆主要改z坐标；`RenderKarstVolume.ts`的相机沿z轴看向游戏平面，主要变化沿视线发生，只剩较弱透视和受光变化。前半身参与少，正常尺寸下看起来仍像刚体。
- 整鱼朝向由目标移动直接更新，后躯弯曲再响应角速度，未做出清楚的发力、身体弯曲和尾部跟随时序。调整平移速度不能补足这项缺口。
- 本次没有制作Blender骨骼动画；现有运行路径是CPU程序顶点变形。但缺少骨骼管线并不是不可实现的证明，程序变形也需要正确的动作设计和镜头验证。这次没有做到。
- 相位连续、滑行数值、网捕和续档检查只能说明工程行为安全，不能证明鱼游得可信。以后重启应先固定整鱼位置和朝向，在实际镜头看清身体循环，再叠加路径；当前不继续调参或录新鱼视频。

## 已有代码实验（不等于动画验收）

- 食人鱼/好奇鱼共用的普通目标移动增加短推进与滑行节奏：停推进仍有惯性，前向与侧向速度按不同阻力衰减。加速、转向及低于巡游速度时优先推进。其他三种鱼保留原目标移动；攻击判定、扑击专用逻辑、鱼网与碰撞仍走原路径。
- 瞬态动作按逻辑步积分连续摆尾相位，结合实际位移速度、加速度、角速度和推进强度平滑调整身体。状态切换不再将增长中的动画时间突然乘以另一个倍率；滑行不因鱼还在移动就保持强尾摆。
- 后躯沿短弧弯曲，断面随弧转动；胸鳍围绕根部展开/收拢，转弯时有有限滚转。头部仍跟随原游戏朝向；没有额外挪动整鱼来掩盖轨迹或碰撞问题。
- 捕获、眩晕、绑缚、手持与出水状态减弱自主推进表现，实际网捕的受力形变继续优先使用原contact。牵引修正不会被当成鱼主动加速。
- 动作状态存在WeakMap中，不改变鱼存档结构，不在渲染中积分；暂停与重复绘制保持姿态。读档新对象建立有限初始状态，未承诺逐帧复原旧动作相位。

两种实体鱼保持原800顶点/1,308三角及现有材质，没有新增贴图、鱼种或三维玩法深度。本轮没有重做鱼造型，仍使用原XY行为/碰撞。

**对照边界**：25秒观察脚本只给目标位置、速度请求及阶段时间，实际移动、转向、碰撞和姿态仍调用生产代码。新旧对照只切姿态，两端使用相同的新运动规则，不能称为旧运动系统的完整前后对比。该入口暂时冻结世界自动循环并关闭鱼的手电/近身触发来隔离动作，绘制时恢复原灯光；它不是自主AI纪录片。真实AI与实际网捕另由原浏览器回归检查。

```sh

node scripts/checkFishVolumeMesh.js
node design/fish-motion/capture.cjs
```

复录的录像、采样轨迹、关键帧、报告和可同播的新旧对照页写入 `node_modules/.cache/fish-motion/`，不会自动覆盖本目录保留的成片。截图与录制来自实际游戏画布，未另造演示渲染器。最终三段录制各250个轨迹采样，完整覆盖左右转向和有位移的无推进滑行，单鱼实际渲染及浏览器错误检查通过。
