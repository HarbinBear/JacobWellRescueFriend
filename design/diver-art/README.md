# 潜水员造型小样 V01 · 2026-11-12

本轮只评审潜水员的轮廓、比例、装备和在实际洞室里的可读性。造型尚未获用户认可。

## 当前小样

- 灰绿与炭黑潜水服、浅色单瓶、少量赭黄标记；单张侧视透明稿。
- 原图在 [`v01/diver.png`](v01/diver.png)，由内置 imagegen 生成，完整提示词在 [`v01/prompt.txt`](v01/prompt.txt)。本轮只生成一版。
- 浏览器评审使用实际 `game.ts`、地图、移动、碰撞、相机和灯光暗罩，只在评审 bundle 中覆盖玩家的画法。可同机位切回原人物。
- 图片保持固定悬停姿势；实际移动时随玩家位置和二维朝向变化。**尚未制作网格、骨骼、踢腿、三维转身、体积受光和深度遮挡**。移动录像只用于看游戏尺度，不代表动作完成。
- 贴片不覆盖正式人物的完整交互动作、装备变化和救援姿势，因此不作为正式角色替换。正式源码和手机包体不加入此资产。

## 打开实际游戏小样

先执行 `npm run shaders && npm run karst:preview`。在仓库根目录运行静态服务器（现有端口为 60972），打开：

`http://127.0.0.1:60972/node_modules/.cache/karst-review/live/game.html?diver-art`

小样初始定格，使用页面上的正常镜头/近景、原人物/新稿、开关手电按钮比较。点击“继续游动”后，WASD 或触控拖动仍走实际游戏输入。独立 `diver-art-review/` 浏览器存档与原评审入口隔离。

预览、截图、录像与验证报告放在 Git 忽略的 `node_modules/.cache/diver-art/`，不随任务提交。

已验证同机位切换、正常/近景、关灯、真实键盘移动与朝向变化、图片加载失败回退，以及原绳索入口不加载图稿。`typecheck`、评审 fixture 独立类型检查、`native:check`、`package:check` 通过；包体静态估算仍为 8,225,216 字节。浏览器验证不代表微信真机验收。

## 下一步边界

先由用户判断真实游戏尺寸下的造型方向。未经美术反馈，不扩展多方向贴图或完整人物管线。需要调整时优先改这一个小样；方向认可后再制作可审核的模型、权重和短动作，不能把程序拼人体或平面旋转称作最终三维人物。
