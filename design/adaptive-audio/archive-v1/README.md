# Signal Below · 生命信号分层音乐草案

这是第一轮音频原型：原创程序化电子音乐，已导出独立资产并接入距离探测。没有使用外部 AI 音乐服务。音色与编曲可以继续试听迭代；微信真机上的音频启动、性能与听感仍需验证。

打开 `listen.html`，点击“开始试听”，然后手动切档或启动自动接近演示。文件自包含，不需要本地服务器；下方能单独听每条 WAV。`Signal-Below-demo.wav` 是 72 秒的递进编排试听，每 8 秒切换一级。独立 WAV 是原始相对电平，试听混音总增益为 0.68，不要逐轨归一化。

## 音乐结构

固定 120 BPM、4/4 拍、E 小调，8 小节 / 16 秒无缝循环。和声为 Em9 → Cmaj9 → Gmaj9 → Dadd9，各占两小节。底轨由持续和声与稀疏铃音旋律组成；整体风格为水下电子 / melodic techno 草案，满层增加推进感，不靠改变播放速度。

| 档位 | 累加音轨 | 本层主要节奏密度 | 听感 |
| --- | --- | --- | --- |
| 0 | bed | 慢速自由留白旋律 | 水下搜寻，持续存在 |
| 1 | + beacon | 每 4 拍 / 30 次每分钟 | 稀疏、有辨识度的信标 |
| 2 | + bass | 每 2 拍 / 60 次每分钟 | 出现低频脉动 |
| 3 | + drums | 每拍 / 120 次每分钟 | 底鼓与军鼓形成推进 |
| 4 | + arp | 每半拍 / 240 次每分钟 | 琶音驱动接近感 |
| 5 | + spark | 每四分之一拍 / 480 次每分钟 | 密集细拍与高频碎光 |

表中的次数是主要节拍网格密度，带延迟、军鼓和装饰音的音轨会包含更多实际起音；不是医学心率，也不复刻视频中的动物心率。各层使用共同节拍的整数倍/分数关系，比无关 BPM 的直接叠加更容易和谐。不是总共五首歌，而是 bed、bed+1、bed+1+2……bed+1+2+3+4+5 六种混音。

## 游戏行为

- 迷宫 `play` 阶段持续底轨；范围外只有底轨。进入探测范围后至少一级，越近越多层。
- 使用原有 `npcRescueRange` 与 `rangeMultiplier`。线性强度 `t = clamp((maxDist-distance)/(maxDist-minDist))`，名义边界 0.2 / 0.4 / 0.6 / 0.8，两侧各 0.03 滞回；因此实际升档点 0.23 / 0.43 / 0.63 / 0.83，降档点 0.17 / 0.37 / 0.57 / 0.77。
- 档位请求在下一拍切换，提前保留 25ms 调度余量，90ms 交叉渐变。请求合并，已排入下一拍的切换完成后再处理最新请求。通常等待不超过约 0.525 秒；连续快速请求可多等一拍。
- 六条循环从同一个 `AudioContext.currentTime` 启动；静音层仍运行，只改变 gain。没有六个独立播放器的时间漂移。
- 玩家发现 NPC 后继续响应；绑绳成功后节奏层撤出，底轨继续。离开下潜、失败、上浮、切后台停止音轨，下一次下潜重新从底轨开始。
- 全局静音开关生效，音量乘 `CONFIG.audio.bgmVolume`。`CONFIG.lifeDetector.music.enabled = false` 可回到旧探测音。Web Audio 不支持或合成初始化失败时自动回退；首次准备完成前暂用原探测音。
- GM 面板“探知仪”中可直接切换“分层音乐”、调整“音乐音量”和“分档缓冲”。原有间隔/频率参数仅影响回退双音。
- 现有 HUD/LED 仅改读音乐时钟的脉冲，不增加新的视觉设计。

## 资产与运行时

`stems/*.wav`：六条 mono / PCM16 / 24kHz，每条 384,000 样本 / 16 秒；允许相位一致的叠加和尾音跨循环。全部 WAV 共约 4.6MB。低频居中是当前 mono 草案的有意取舍，正式音色可升级为 stereo / 48kHz。

游戏不加载这些 WAV，而是分块运行 `src/audio/AdaptiveScore.ts` 生成同样的 PCM，然后创建六个循环 AudioBufferSource。Float32 音轨常驻数据约 9.2MB，生成过程中还存在临时单轨缓冲；后台停止播放但保留缓存。每批约 5ms 计算预算，首次触摸后异步准备；实际帧时需真机实测。

`design/` 已被项目现有微信打包配置排除，试听 WAV 不进入主包。`manifest.json` 记录时长、调性、格式与音轨顺序。可把 WAV 导入 DAW，用合成器替换音色或重新录制，但要保持固定 BPM、共同起点、相同长度、完整静默区与跨循环尾音。新制作的 WAV 可由加载器解码后交给 `AdaptiveMusicEngine`；当前游戏适配器仅走程序合成，尚未做云端资产加载。

## 后续视觉接口

`getAdaptiveMusicClock()` 返回 `playing / level / requestedLevel / beat / bar / beatPhase / subdivisionPhase / pulse / bpm`。`beat` 为本次播放起点以来的绝对拍号，`bar` 在 0–7 循环；`pulse` 由当前档位主要网格计算。未来视觉应每帧查询音频时钟，不能用独立 `Date.now` 计拍；这是运输时钟，未校准设备输出延迟，也不代表每个装饰音。需要逐音符视觉时可从同份乐谱导出事件。

这套引擎与距离计算分离。未来可把深度/心率/氧气风险映射为 `setLevel(0..5)`；若同时映射多个信号，需要先定主次，避免玩家无法判断音乐到底在提示接近还是危险。

## 重建与检查

```sh
npm run audio:build
npm run audio:check
npm run typecheck
```

`audio:check` 验证音轨与导出样本一致、所有累加档位峰值、循环接缝、滞回、同一时刻启动、按拍切换、静音保留时钟及停播重启。控制器测试使用 Web Audio 替身，不替代微信真机验证。

工具选择：本轮直接编曲和合成可精确控制分层；若继续追求更成熟的音色，可在 Ableton/REAPER 等 DAW 中沿用这份乐谱；Suno Studio 能导出 multitracks（https://help.suno.com/en/articles/13925249），但导出的音乐仍应检查共同拍点、循环与混音。Wwise/FMOD 提供成熟的互动音乐组织和切换能力；当前微信小游戏原型先采用项目已有的 Web Audio 路径。
