# Signal Below III · 第五轨前景化

这一轮根据用户提供的 13.7 秒参考录音与“第五轨听不出来”的反馈，集中重做第五轨。前三版主题和前四轨原始音频保持不变；第五轨上移八度，强化二至五次泛音与短促起音，减少尾音糊连，并增加原始乐谱增益。五级时底轨和第四轨退后，突出前景。

上一轮三版试听、源乐谱与引擎保存在 `archive-v2/`；最初一轮保留在 `archive-v1/`。

先听 `reference-study/four-old-five-new-five.wav`：同一乐句每段 8 秒，依次为四级、旧五级、新五级。各段从相同乐句起点开始，不是连续游戏切档；没有强制匹配段落响度，保留加层动态。每个版本另提供 `four-to-five.wav`（16 秒连续四级→五级）及 `fifth-solo.wav`（8 秒第五轨单独试听）。

当前环境没有可直接主观听取录音的工具；已本地解码和测量，判断基于用户反馈、信号数据与乐谱。参考是手机录制的完整混音，不能识别其中第五条独立轨，也不把频谱测量当作听感验收。没有从参考中分离、截取或采样声音用于新音乐。详见 `reference-study/README.md`。

这是原创程序化合成的三版试听稿，没有调用外部 AI 音乐生成服务。弦乐由带谐波滚降、失谐与颤音的合成器模拟，后续可继续替换为采样弦乐或更成熟的合成器音色。

## 先听哪里

打开 `listen.html`，顶部可直接播放三个版本，无需等待实时合成：

| 版本 | 写作方向 | 调性 | 试听目录 |
| --- | --- | --- | --- |
| A · 深流 | 幽暗弦乐主题、规则低频推动，接近时转为强推进 | D minor | `undertow/` |
| B · 微光奔涌 | 长线条上行旋律，突出发现目标的激动与希望 | E minor | `flare/` |
| C · 最后航线 | 低弦短句、切分低音与碎拍，突出争分夺秒 | C minor | `pursuit/` |

每版仍提供 `theme.wav`（16 秒纯底轨）、`climax.wav`（12 秒最高档）、`demo.wav`（56 秒逐级叠加）。三版满层 RMS 差约 0.18dB，便于在接近的整体能量下比较风格；没有逐轨归一化，保留编曲电平关系。这是未经响度加权的 RMS 对比，不是 LUFS 测量。

递进试听：0:00 底轨 → 0:08 一级 → 0:16 二级 → 0:24 三级 → 0:32 四级 → 0:40 五级，最后一级持续 16 秒。每次加层保留原轨，不更改整体播放速度。

试听页下半区可以选择版本、手动切档、模拟距离、自动接近，以及单独听六条音轨。实时播放器与游戏共用乐谱和同步引擎；首次播放需要分块生成 PCM。换版停止旧引擎，各版缓冲只在试听页中缓存；游戏只缓存默认 A 版。

## 编曲与节奏

共同音乐时钟 120 BPM，4/4 拍，8 小节 / 16 秒无缝循环。A 版和声为 Dm(add9) → Bbmaj7 → Gm → A7，各两小节；B、C 版分别移调，但重写主旋律和部分节奏。属和弦留有未解的张力，循环回主和弦时获得释放。

| 档位 | 累加层 | 主要音型密度 | 本轮变化 |
| --- | --- | --- | --- |
| 0 | bed | 长音与完整旋律短句 | 电子弦乐主旋律、低弦与和声，去掉轻巧铃音 |
| 1 | + beacon | 30 次/min | 每小节一次有重量的双心搏信标 |
| 2 | + bass | 60 次/min | 加入低弦脉动和饱和低音 |
| 3 | + drums | 120 次/min | 重底鼓、军鼓与反拍帽镲；C 版使用碎拍 |
| 4 | + arp | 240 次/min | 八分弦乐音型、低音疾行、上方弦乐与鼓花 |
| 5 | + spark | 1200 次/min | 高八度前景金属/锯齿疾奏，强化短起音、重音与高次泛音；其余轨让位 |

这里的 1200 是最高层有音高音型的起音密度，每秒 20 次、16 秒共 320 次；不是把所有轨道改成 1200 BPM。第四层主要音型每秒 4 次，因此第四到第五层的主要起音密度增加五倍。装饰音、双心搏与附加打击乐另计。

第五层采用每拍两组五音音型，第一音与第六音带重音；底鼓维持可辨识的大拍结构。高密度层负责兴奋、奔涌，低频节拍负责身体律动。它带五连音质感，是否接近用户参考视频仍需以试听反馈为准。

## 游戏行为与接口

游戏默认使用 A · 深流。此次重写共用乐谱后，游戏内合成也会更新；未做视觉样式改造。

- 迷宫 `play` 阶段保持底轨；探测范围外回到底轨，进入范围至少一级，越近越多层。发现 NPC 后继续响应，绑绳成功后撤出节奏层。
- 沿用原有 `npcRescueRange` 与 `rangeMultiplier`。距离强度线性分档，边界 0.2 / 0.4 / 0.6 / 0.8，各有 ±0.03 的滞回缓冲，避免来回跳档。
- 六条 BufferSource 共用音频时钟同一时刻启动，始终循环；切层仅控制 gain。下一拍切换，预留 25ms，90ms 渐变。已排队的切换先完成，新请求合并。
- 五级混音比例为 `[0.72, 0.78, 0.9, 1, 0.55, 1]`（底轨至第五轨）。底鼓保持，主旋律和第四轨退后；退出五级时在同一拍边界恢复，底轨不会被关闭。离线试听与游戏共用 `SCORE.levelMixes`。
- 全局静音继续保留时间轴；离开下潜、失败、上浮或切后台停止。下次播放重新从循环起点开始。
- GM 面板“探知仪”可切换“分层音乐”、调整音量和分档缓冲。默认音乐增益从 0.68 调至 0.78；仍乘 `CONFIG.audio.bgmVolume`。
- 不支持 Web Audio 或初始化失败时回退原探测音；首次准备完成前暂用原探测音。

`getAdaptiveMusicClock()` 返回 `playing / level / requestedLevel / beat / bar / beatPhase / subdivisionPhase / pulse / bpm`。最高档时钟已同步改成每拍十次。`beat` 是播放以来的拍号，`bar` 在 0–7 循环；未校准设备音频输出延迟。未来视觉可读这个时钟，逐音符联动可从导出的乐谱事件计算。

## 资产、性能和检查

三版各有六条 mono / PCM16 / 24kHz WAV，每条 384,000 样本 / 16 秒。`manifest.json` 记录音轨、调性、节奏分割与电平。根目录 `stems/`、`manifest.json` 与 `Signal-Below-demo.wav` 是默认 A 版的兼容入口。

游戏不读 WAV 或网络，而是从 `src/audio/AdaptiveScore.ts` 分块合成同样的 PCM；每批约 5ms 计算预算。六轨 Float32 常驻约 9.2MB，合成时另有临时单轨缓冲。弦乐合成比上一版更复杂，首次生成的耗时和帧率仍需微信真机实测。导出资产均在现有配置排除的 `design/` 中，不进入微信主包。

离线检查覆盖三版全部累加档位的混音峰值、接缝、PCM/WAV 一致性、底轨旋律事件、最高层实际 50ms 起音间隔、试听时长、按拍切换、静音和重启。控制器使用 Web Audio 替身测试；未把程序校验当作主观音色验收。

2026-10-18 用户确认手机可以运行。此前真机远程调试的 `getSystemNanoTime` 异常定位到微信调试基础库的性能记录链路，建议使用普通预览扫码运行后收到上述反馈；未确认远程调试链路已修复，也未完成真机合成耗时、内存和各档音色的系统验收。窗口信息读取已优先采用 `wx.getWindowInfo()`，保留旧接口与尺寸兜底，并用 `npm run platform:check` 校验。

```sh
npm run audio:build
npm run audio:check
npm run typecheck
npm run build
```

`audio:build` 会重建三版试听与独立轨，不改写两个 archive 目录。有 `archive-v2/` 时同时重建旧新对比。参考信号分析脚本为 `scripts/analyzeAdaptiveAudio.py`，需要带 NumPy 的 Python 环境；不属于游戏运行时。
