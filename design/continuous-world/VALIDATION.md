# M1 验收记录

日期：2026-11-09。范围：当前真实游戏模块的独立连续章节接入，桌面隔离浏览器验证。不是微信真机验收，也不是最终美术批准。

## 通过项目

| 项目 | 验证方式与结果 |
| --- | --- |
| 完整编译 | 独立模块与临时接入后的整个实际游戏均通过 TypeScript 检查 |
| 真正光照 | 确认 WebGL 路径开启，水面下使用逐像素世界深度环境光 |
| 共享岸坡 | 2,400 个圆体采样与原多边形几何完全一致，无差异 |
| 原洞连通 | 只走新接缝以下的真实深洞，仍可连通原救援目标，不借岸外空白格绕路 |
| 自然进出水 | 原生键盘轨迹包含半浸没、游泳、返岸；阶段始终为 play，没有入水转场或出水结算 |
| 三鱼牵引 | 三条不同腰绳实际拖上岸；鱼保持绑定与稳定 ID；再次入水与强力返岸不销毁鱼 |
| 原位读档 | 分别在岸上和水下恢复位置、速度、气量、鱼、绳端对象引用、背包、救援与探索 |
| 离线暂停 | 后台等待后重复保存，世界时间、鱼状态、剩余眩晕与体力均不偷偷推进 |
| 消耗持久化 | 已消耗气瓶恢复为已使用，背心标准气量和氮负荷保留 |
| 实体补气 | 实际移动到充气架，原生 E 输入触发渐进补气，不远程或瞬间刷满 |
| 背包兼容 | 原生触控打开和关闭原背包，场景与牵引不重开 |
| 救援交接 | 实际移动到帐篷，再交接；目标完成后仍在同一世界，不触发旧战利品结算，不清鱼身腰绳 |
| 横竖屏 | 原生触控切屏，世界对象图与章节保持不变；另采集实际竖屏玩法，不把总览当作竖屏操作验收 |
| 原版保留 | 原移动、体力、背包、旧救援闭环、鱼交互、窗口、切屏、岩体与包预算检查通过 |

原生移动验收不通过修改坐标跨水面。三鱼和救援场景使用明确标注的验收布置，资源状态测试含测试夹具；不能把这些布置按钮当成游戏里的捕获或传送能力。

## 边界

当前人物和鱼仍沿用原游戏绘制基础，新增环境贴图与动作融合属于可玩方向样本，尚未达到正式美术定稿。深洞表现仍需后续继续打磨。

正式 game.ts、src、原素材和微信配置未替换；新工程与素材在独立设计目录，预览、逐帧轨迹和临时截图在被 Git 忽略的缓存目录。手机包前编译估算仍为 8,252,177 字节，没有因本轮实验增加。

本场景运行图片的 RGBA 解码估算约 11.75 MiB，不等于整个游戏的实际内存，也不代表手机 GPU 内存已经通过。正式接入必须治理包体并做微信真机加载、帧率与触控测试。

正式旧档迁移、跨章节出发、失败恢复、鱼档与烧烤等资源转化、完整交易和多人联机尚未接入，本节点不将它们写为完成。

## 复现与记录

```bash
npm run world:check
npm run world:browser
```

最新自动报告与逐帧轨迹分别为缓存中的 `acceptance/report.json` 与 `acceptance/movement-trace.json`。命名版本用 README 中的 `--ref` 命令复现，并冻结该提交的代码、GLSL、素材和独立存档命名空间。

`review/` 中仅归档本轮需保留的场景总览、三鱼上岸和真实竖屏玩法截图；它们是实际游戏画面，不是另画的概念场景。
