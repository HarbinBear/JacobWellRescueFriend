# 连续章节世界：林泉营地

日期：2026-11-09。状态：M1 空间与交互验收版本，不是最终美术定稿，不替换已跑通的手机版。

## 核心规则

一个洞穴就是一个章节；岸上、泉水和深洞属于同一个世界。入水、出水只是玩家身体所处介质发生变化，不是开始或结束一局。

救援目标真正移交岸上营地后，章节目标才完成。完成不关闭泉井、不清空鱼与绳网、不强制进入下一洞穴。玩家可以留在本洞继续活动，再主动选择下一章节。

退出、后台和重新进入只暂停与恢复世界。位置、气量、背心气量、氮负荷、体力、背包、已消耗补给、鱼的状态、绳网和救援进度不因“再进一次”自动刷新。

## 为什么选宽浅滩

主路线选择“营地 → 石质缓坡 → 涉水带 → 浮游带 → 泉井”。它既有自然水深变化，又能让多条鱼和救援对象跟着绳索通过。入水不需要按钮，上岸不需要切场景。

不选窄梯子作主入口：它会把多实体牵引挤在一点，迫使所有鱼和被救者先做复杂的跨梯搬运，既容易穿模，也削弱自由进出水的感觉。

码头与宽台阶适合以后作为第二出入口、多人集合点或设备装卸点。它们不是另一套传送系统，也不能成为唯一上岸路线。

## 空间结构

```text
鱼档预留   医疗帐篷       装备铺     调查板   充气架
─────────可行走的林地营地──────────────╲
                                         ╲ 涉水带
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~╲~~~~水面
                                           ╲ 浮游带
                                            ╲ 泉井
                                             │
                                             │ 连到原有洞穴
                                             ╰─ 深洞分叉与救援目标
```

营地面积按“能顺畅带着牵引实体移动”来留，不围着一张全屏 UI 排按钮。医疗帐篷在岸上内侧；充气架靠近浅滩；地图板在进入泉井前的必经路线；装备铺与未来资源转化点沿营地外侧展开。

原有洞穴种子、主要通路和深处救援位置保留。本节点只重构入口前庭与连接段，不推倒已认可的岩体方向，也不把海水备选生物混进新的淡水生态主稿。

角色、鱼、绳端、通视和手电遮挡共同读取岸坡采样轮廓。不能把视觉上的岩石画在物理水路里，也不能让鱼、绳索或灯光穿过看得见的岸坡。

## 连续运动设计

岸上采用强阻尼、明确落脚的步行。摇杆或空白拖动的横向分量控制左右，脚步由实际位移推进，不在站着不动时原地踏步。

浅滩中先脚踝和小腿没入水，再到腰胸。行走减速、步幅缩短，水面按世界坐标只覆盖浸没部分。人物保持同一个骨架与气瓶，不在两张角色图之间硬切。

水深足够后，脚不再维持地面接触，身体渐渐前倾浮起，接入原有手动、半自动或自动游泳。回程先游向浅坡，接触坡面后转为涉水与行走，镜头不跳位置。

水面判断以身体浸没比例和头部位置为准，头部状态加小范围迟滞，防止浪纹让呼吸、动画和音频反复闪切。空气中不消耗气瓶，也不自动补满；玩家必须实际走到充气架接管补给。

## 牵引与救援

鱼一直是同一条鱼。离水后失去水体浮力，受到空气重力与地面摩擦；仍可挣动，鱼身结和腰扣仍相连。重新入水恢复水中运动，不重新生成鱼。

多条腰绳分别保持自己的长度、端点、张力和路线。绳子可以跨水面，实体因牵引逐步移动，不能为了上岸直接把鱼吸到玩家身上。岸坡要足够宽，避免把正常拖行做成必须通过单点的卡关。

新介质中要区分响应质量：几条普通小鱼不能像几名潜水员一样把玩家钉在水面。当前点式解算按鱼的体型类别调整牵引响应系数，固定岩石锚点仍能约束玩家；这不是宣称已经做了精确公斤级刚体模拟。大型鱼、巨物和多玩家牵引在后续按实际资产比例另做验收。

救援对象同样沿安全绳被实际带回岸上。玩家自己浮到旧出口不会完成救援。医疗帐篷接收对象后，才写入章节完成标记；鱼身牵引、背包和世界保持不变。

本节点有明确标注的“三条腰绳”和“岸上交接”验收布置按钮。它们仅在独立浏览器侧栏中布置测试实体，不是游戏的捕获、传送或快速上岸能力。正常移动与跨介质验收使用原生键盘、触控及真实物理。

## 视觉设计

主色为淡水泉绿、灰绿林冠、暖米色石灰岩和旧黄铜。岸上是有空气、斜阳与日常生活的空间；浅水透亮但不发霓虹光；深处颜色逐渐收敛到冷绿蓝与手电。

远景林地使用独立绘画图层并随镜头产生轻量视差，不是带人物、营地和完整水面的单张概念图。人物、营地实体、岸坡、水体与波纹分别合成。

岸坡先解决可读的大形与厚度，再补材质：顶面、厚侧面、接触阴影、侵蚀弯曲和湿润后的颜色衰减共同表达空间。不能拿更多裂纹盖住平面，也不能拿统一的锯齿轮廓装自然。

营地实体采用有织物、木纹、金属与旧物细节的独立贴图。装备铺有屋顶、柜台、挂着的潜水服和气瓶；医疗帐篷有真实出入口与接收位置；地图板和充气架各有清楚的体量。

水面是世界里的边界，不是全屏蓝色遮罩。角色和绳索先绘制，再用水面前层与水下颜色覆盖浸没部分；破水、涉水脚步和牵引物落水产生局部波纹与水花。

本节点已有可玩视觉样本，但仍需用户确认空间比例、镜头距离和整体美术方向。后续定稿应继续改善岸壁构造、角色陆地姿态以及深洞连接处的美术，而不是把当前样本宣称为惊艳定稿。

## 渲染与性能

保留 Canvas 2D 场景和现有 WebGL 水下光照，不引入另一套引擎或完整骨骼运行库。静态营地和岸坡走 drawImage；人物沿原骨架增加脚步与涉水姿态；动态波纹保持少量世界空间图元。

水下光照只合成在水面以下，不能因为玩家潜深了就把岸上天空压黑。坡面多边形参加手电射线、绳端选择和通视，不能被误当成一个巨大的包围圆。

岸坡查询使用二分采样与局部边段，旧洞碰撞使用邻域栅格和对应额外岩块。远处未绑定鱼暂不执行完整近景行为，绑定与牵引实体持续模拟，不删实体也不重置其状态。

本节点的实验素材只进入 design 和被忽略的预览缓存。正式包的前编译估算仍为 8,252,177 字节，8 MiB 上限下仅剩 136,431 字节；按现有 128 KiB 安全预留，实际上只多约 5 KiB。正式接入前必须治理包体，不可直接塞入这批图片。

文件压缩体积不等于运行内存。资产清单单独记录 RGBA 解码内存。真机帧率、GPU 内存、微信加载与横竖屏触控必须作为后续验收，桌面浏览器通过不能替代真机通过。

## 存档设计

采用“洞穴种子 + 章节增量 + 稳定实体引用”。不保存巨大的地图墙体矩阵，而用同一生成器与入口布局重建，再恢复状态。

玩家保存位置、朝向、速度、气量和最大气量；鱼保存稳定 ID、位置、行为、绑定与剩余眩晕时间；绳网保存端点、路径、绳长及到鱼和岩石的引用；救援对象保存位置、绑定和关节状态。

保存背包、经济、剧情进度、探索位图、已使用气瓶、图鉴、体力、BCD 标准气量和氮负荷。主档写入前保留一份有效备份，损坏时先检查备份，不主动删除旧档。

本节点用独立浏览器命名空间与独立章节 key，正式游戏旧档不被改写。正式 v3 档迁移方案是：先备份旧档，保留 seed 与累计探索、绳网、图鉴、经济和剧情；旧档没有可恢复的完整世界对象图时，在新营地安全位置首次构建一次，之后才能按退出位置精确续接。该正式迁移本节点未执行。

离线期间世界暂停，不偷偷游动鱼、扣气或减少眩晕时间。后台时清除持有触点，不把“松手”当作补满体力；重新进入时按剩余时间重新锚定动作计时。

## 商业与联机边界

鱼档、水族馆、烧烤摊与装备买卖是后续系统，本次只留物理位置和实体交互入口。未来出售应由鱼确实抵达接收点触发一次性所有权转移，而不是玩家站在任意地方点“全部卖出”。

联机采用房间世界、玩家、鱼、绳、营地设施的稳定 ID 和明确所有权；资源转化、救援完成和章节迁移由权威端幂等确认。绳索跨玩家时需要统一物理权威与校正策略，不能把当前单人对象引用直接当网络协议。

本节点仍是单人实验。没有实现多人同步、服务端、房间管理、联网存档或跨设备同步。现在先避免“下潜即重置”造成的生命周期死结，为以后联机留下合理边界，但不声称已经联机就绪。

## 验收节点

M1：确定空间路线。实际试玩行走、涉水、游泳、拖鱼上岸、原位存档、医疗交接和同一场景的横竖屏。用户优先判断宽浅滩是否符合预期，以及营地和泉井的比例、镜头和风格。

M2：正式接入。治理包体、推进岸壁与陆地人物美术定稿、落地正式存档迁移、章节选择与失败恢复，并进行微信真机验收。是否增加码头与第二上岸路线在这个阶段决定。

M3：实体商业。装备陈列与购买、鱼档、水族馆、烧烤和物理资源转化；多实体交付、所有权和防重复结算都要先验收。

M4：多人联机。房间世界与权威同步、绳网协同、多玩家接收、重连和存档一致性。另立网络协议与性能验证，不混进这次空间重构。

## 用户验收建议

先直接从浅滩走进泉水，再游向岸坡回来，观察控制、身体与镜头是否连贯。接着在侧栏布置三条腰绳，向左把鱼拖到干燥岸上，再原路带回水里。

分别在岸上和水下使用“保存并原位续接”，核对位置、鱼、绳子和气量。走到地图板、充气架和帐篷附近，确认交互来自实际距离，不来自岸上的全屏按钮。

本节点应停止让用户拍板的是空间和视觉路线，不是要求用户接受一个未完成的最终版本。交易、跨章节、失败恢复和多人联机明确留到后续，不把这些缺项写成已完成。
