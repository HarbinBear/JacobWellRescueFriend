# 手机版玩法接入 v1.0.21

本轮按用户最新决定收缩范围：玩法优先，接受当前背景；水下恢复原圆形岩石，人物恢复原潜水员，岸上只补可用步行姿态。暂停新岩体、新角色和美术管线尝试。

## 当前入口

直接打开项目根目录的微信小游戏工程。主菜单点「进入林泉营地」或「继续章节」，使用实际 game.ts 和 src/world/continuous 进入连续章节；不是独立 demo，也不需要临时替换源码。

旧测试档不迁移。新章节使用 continuous_gameplay_mobile_v1 独立 key，主菜单「新游戏」可清档开始。气量耗尽提示另有明确的「重新开始测试章节」，不是自动上岸或正式失败结算。

## 跑通的玩法范围

岸上左右行走，沿浅滩自然入水，水下保留原游泳、气量、BCD、手电、鱼和绳索操作；游向浅坡可落脚返岸，不按次结算、不用入水上岸传送按钮。

三条鱼的腰绳跨水面保持，真正拖鱼返岸，再次入水和退出续接时维持绑定、绳端引用、物理路线和鱼 ID。原位恢复包含探索、背包、气量、体力和救援状态。

地图板、充气架与医疗营地仍是可走近交互的实体。充气需要走到充气架渐进完成，救援对象需要实际带到帐篷旁交接；装备铺目前是陈列交互，交易、价格和换装尚未接入。

手机保留原背包、工具盘、随身听、手电、设置与横竖屏。浏览器额外测试布置放在 scripts 与缓存，不进入手机包。

## 不做新美术

背景沿用已被接受的原画与镜头投影，母版不改写。岸坡图片沿用既有方案，只做末端淡出、原圆岩淡入的简单过渡，暂不统一岩体美术。

原圆岩通过既有 drawMazeWallShape 渲染，原潜水员通过 drawDiver 渲染；不加载 M2 的连续石灰岩材质、GPU 地形表面或新人物贴图。脚蹼保留尺寸，不用上岸缩小冒充穿脱。

Canvas 本身可以绘制 PNG/JPEG、图集动画和分层关节。原人物大量用路径与基础形状绘制，当前局限主要是素材与造型制作方式，而不是 Canvas 必然只能做简陋画面。完整原画概念、造型、绑定、动画和资源管线留到后续专项。

## 包体

既有夜景和少女素材本来是不透明 RGB PNG，改为相同尺寸高质量 JPEG；原 PNG 保留在仓库、只排除出运行包。没有删除剧情代码或原图。

岸坡使用原图的 RGB JPEG，并由同一个岸坡轮廓裁切，避免携带两张大透明蒙版。新场景运行图片约 1.08 MiB；整个项目的预编译文件估算约 5.94 MiB，保留现有 128 KiB 安全阈值。微信开发工具最终编译大小仍以实际输出为准。

## 验证与未验收项

已用当前手机源码的隔离浏览器验证主菜单原生进入、行走、半浸没、游泳、返岸、三鱼牵引、岸上和水下原位恢复、后台暂停、实体补气、背包、医疗交接及横竖屏。

恢复原圆岩后的 6 个深度、7,200 帧多方向模拟另行验证，不能借用 M2 新几何的通过结论。原移动、鱼交互、背包、窗口切屏、旧迷宫和保底岩体回归也要通过。

微信预览调用目前未正常返回二维码。工程已经进入手机代码与包范围，但不能宣称微信真机帧率、内存与触控通过；需要在开发者工具正常编译并由手机验证。

完整交易、鱼档资源转化、装备穿脱、正式失败恢复、跨章节出发和联机仍不在本轮范围。

## 运行与留存

```bash
npm run world:browser
npm run world:stress
npm run package:check
```

网页验收端口使用 60972，入口为缓存中的 continuous-gameplay/game.html；它编译实际主工程，没有岸水源码适配。原始测试报告与截图放忽略缓存；需要保留的摘要归档到 review/mobile-gameplay。

M1 与 M2 的代码和美术仍保留在原标签 world/shore-m1-20261109、world/shore-m2-20261109，不重写旧版本，也不把它们当成已批准的新版美术。新手机版玩法单独提交、命名留存，不混入用户待办修改。
