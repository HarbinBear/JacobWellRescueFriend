# 断冠双岔洞：岩体美术保存基线

2026-10-24，用户反馈本版“稍微满意一点，已经往正道上走”，要求先提交可回退版本再继续优化。这是方向基线，不是最终美术、正式全图或微信真机验收。

本目录保存实际同源研究的代码、最终贴图、离线烘焙入口和原始参照画面。正式 `game.ts`、`src`、全图生成和绳索行为未替换。

## 运行

使用已有项目依赖。浏览器检查脚本需要 Node.js 22+ 的内置 WebSocket 和本地 Chrome；可通过 `JWR_CHROME` 指定可执行文件。资产已提供，预览无需 Python 或再次生成图片。

在仓库根目录运行：

```sh
node design/cave-room/build.cjs
```

生成纯静态入口 `node_modules/.cache/cave-room-preview/game.html`，用工作区静态服务打开即可。所有游戏角色资源通过相对路径读取原项目；无后端、无生产服务、无存档写入。

在当前本地静态服务端口60972运行检查：

```sh
node design/cave-room/review.cjs
```

`JWR_REVIEW_URL` 可指定部署后的完整研究入口地址。测试仅启动独立无头Chrome，不操作用户正在使用的浏览器。结果写入忽略目录，不覆盖已提交的 `reference/`。

## 保存内容

- `ReviewCave.ts`：实际几何查询、动态法线、短程表面遮挡、抗锯齿、GPU回退和简单碰撞移动。
- `build.cjs`、`review.html`：直接打包正式游戏模块的研究入口，保留原潜水员、HUD和水体手电，并在研究包内插入岩体受光及边缘修复。
- `assets/`：最终色图、法线、接触/高度数据、远景和同一份解析轮廓。
- `bake.py`、`raster.py`：离线生成非平面前面与侧面，背面剔除、深度与法线烘焙；运行游戏时不执行三维网格渲染。
- `finish_assets.py`：将已生成的岩石表面美术限定在同一轮廓覆盖率内，不从颜色猜法线。
- `reference/`：用户认可方向时的三个实际游戏视点、转灯动态图和核验记录。只作基线证据，不作为未来优化已经合格的保证。

## 可选重新烘焙

Python 3.9+，`Pillow==11.3.0`，无NumPy依赖。

```sh
python3 design/cave-room/bake.py
python3 design/cave-room/finish_assets.py
node design/cave-room/build.cjs
```

烘焙会更新 `assets/`，先保留提交再优化。离线表面图已经包含在仓库，不需要重复请求图像生成。

## 当前边界

23个模块构成同一个洞室。几何高度来自空间斜坡与折皱，不套统一低边、高中心、平顶模板；前面较连贯，侧面保留硬转折。最终表面美术是离线生成的图像资产，包含固定颜色、裂缝和局部AO，不是完全物理可重光照的albedo；细节与粗几何法线尚未逐项对齐。

正常画面只用游戏手电和原有近身光参数，不增设摄影棚灯。研究入口暂停正式游戏模拟，方向键移动只验证同一轮廓的身体碰撞，不代表完整绳索、救援、全图地图或手机性能。

后续保留此基线，优先改善细部纹理与法线对应、岩块节奏、远景层次和资源开销。不要又退回平面换滤镜，不在未经对照的情况下直接替换正式全图。
