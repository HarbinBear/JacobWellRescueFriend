# 游戏内岩体试跑（v1.0.19）

## 怎么跑

在微信开发者工具打开本项目并重新编译，主菜单点击“岩体试跑”。经过原游戏倒带、入水和播放流程后，进入断冠双岔洞。

v1.0.19 已做无损减包、开发资源排除及岩体按关卡加载/卸载，静态包体候选约7.75MiB。官方自动预览目前被开发者工具的服务端口关闭拦住，尚未生成真机二维码；请在工具内重新编译并点击预览。详细证据与验证边界见 [PACKAGE.md](./PACKAGE.md)。

这次运行的是正式 `game.ts` 主循环，不是暂停模拟的外部评审包。氧气、体力、BCD、身体移动、墙体碰撞、工具轮盘、铺绳和救援目标使用游戏实际逻辑。开始位置在洞内约54米，初始朝向与已认可岩体基线一致，方便直接看效果。

工具按钮在靠近岩壁并停稳后可用；打开轮盘，上方选“铺绳”，再次靠墙停稳后可选“结束铺绳”。不要按旧代码里未接入触摸的独立圆形绳索按钮。右上角“退出岩体试跑”可在倒带、水下或返岸阶段退出。

普通“一键下潜”和“继续游戏”仍使用原案件。试跑不修改正常随机地图生成算法，也不改旧种子存档格式。

## 保存隔离

试跑使用临时副本运行装备、背包、故事和标记。案件、经济、故事存档在试跑期间禁止写入或清除；退出后恢复原对象和装备参数。可以放心用现有装备试，不会因试跑死亡扣掉正式库存。

本轮不是全图换皮。实际接入了一个可玩的岩体关卡，验证通过后再将更多洞室和地区组织放进普通地图。

## 已落入正式运行的部分

- 原始岩体色图、几何法线、接触/高度和远景贴图放入小游戏打包目录，使用 `wx.createImage` 与 `wx.createCanvas`。
- 真实身体、鱼碰撞、光照、玩法视线、绳索锚点、墙面标记和相机开放度共用岩体多边形轮廓，不使用包围圆作为实际障碍。
- 绳索按几何寻路，失败时不退回已知穿墙的直线；试跑绳索按安全折线绘制，不用弯曲或摆动切进岩壁。
- 保留分数覆盖率抗锯齿；光束采用角向距离插值和连续截断衰减。低画质试跑也保留遮挡。
- 原生表面资源重建和 `gl.flush()` 保证Canvas合成顺序；保留无WebGL时的可见回退。
- 寻路细网格与游戏深度单位分离：20px只用于绳索寻路，游戏仍用120px的既有深度单位，避免将呼吸、浮力和减压深度误放大。

## 检查

```sh
npm run shaders
npm run typecheck
npm run cave:check
npm run game:preview
npm run cave:browser
```

离线检查使用内存存储，验证通路、实体、手电、锚点、视线、绳索、普通地图确定性和存档恢复。浏览器检查实际点击菜单，经过正常下潜流程，观察呼吸扣氧和动作推进，用真实键盘移动和工具轮盘完成开始、移动、结束铺绳，最后退出核对存储与装备恢复；不强制设置play或暂停模拟。

真实游戏浏览器入口为 `design/deeptape/game.html`。构建脚本仅适配浏览器资源与音频，不替换玩法。截图和详细报告位于忽略的 `node_modules/.cache/cave-native-game/`。

## 还不是最终版

用户认可的是方向，本轮完成的是可玩落版，不是最终美术验收。尚未验收微信真机帧率、WebKit长期稳定性、峰值内存、完整救援返程以及全图程序化布置。

接下来优先做三个方向：细部绘制结构与法线对应、不同洞室的主识别轮廓与岩块节奏、真机资源与恢复预算。新的实验保留在独立评审入口，不覆盖已提交基线；对照通过后再逐步迁移到可玩关卡。
