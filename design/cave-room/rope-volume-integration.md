# 固定引导绳体积接入 · 2026-11-12

在实体鱼之后推进绳索的受光与遮挡，现覆盖全段入水、两端固定在墙或已有绳上的引导绳及编网。第二根绳交叉后整网退回二维的问题已修复。

## 表现与玩法边界

静态绳芯沿已有 `rope.path`；编网与绳上固定端复用二维绘制的结点/8单位采样，再调用真实 `getRopeDeformedPoint`，让管体跟随鱼撞网与挣扎。中心保持 z=0，圆截面围绕它展开，不给绳添加虚假的前后摆动。原 `rope.path` 不改写，落锚、绕墙、铺绳、编网、拆绳、碰撞和存档规则沿用。

绳与洞壁、实体鱼共用三维相机、深度缓冲、手电阴影和岩面回光。共用实体鱼着色器的照明计算，但绳用宽而弱的哑光高光及较小阴影偏移；鱼的材质参数保持原值。二维层仅跳过本帧已经画出的立体绳段，墙锚与绳结保留原绘制。

首次近景中细绳有明显单采样台阶，三维画布现申请MSAA抗锯齿，桌面实测获得4样本。`volumeAntialias` 控制启动时是否申请，修改后需重启游戏；平台不支持时照常渲染。此改动也平滑鱼体/洞壁轮廓，没有增加绳半径或改洞形。

静止绳网格复用 GPU 缓冲。路径内容、对象身份、实际受力坐标或可见选择变化时才重传；冻结接触与回弹结束也能复用。其版本参与洞室画面缓存，避免无鱼场景剪掉绳后留下残影。整根超出预算或不受支持时整根回退，不只画前半根；单根采样超限不连带正常交叉伙伴。

绳材质改用高可见黄色，近场手电直射保留固有色，仍受阴影、距离吸收和回光影响，没有自发光。现实中黄色确实存在，例如[XS Scuba Highland Sport Reel](https://www.xsscuba.com/spoolsreels/highland-sport-reel)；[Dive Rite](https://diverite.com/products/reels/azimuth-reels/)也使用白色及橙色，不能把黄色说成唯一行业标准。近场色彩保留是游戏材质选择，不是完整水下光谱模拟。

## 必须保留的限制

- 单条引导绳原本不拦鱼或人；只有编成 woven 网后才参加绳网碰撞。此次不宣称立体缠绕或三维碰撞完成。
- 编网管体已保持三维；腰扣牵引、铺设中的活动绳、跨水面的绳仍走原二维画法。
- 潜水员、墙锚、绳结仍在二维前景，尚不能表现绳绕过手掌或身体背面的完整遮挡。
- UI 入口与探索菜单是流程阶段的临时版本；用户明确指出它与圆形仪表、潜水装备控件风格不一致，已记入 ToDo，不能视作美术定稿。

## 评审方式

`npm run shaders && npm run karst:preview` 后，打开本地预览的 `/node_modules/.cache/karst-review/live/game.html?rope-volume`。侧栏可切原平面绳、宽景、近看与墙锚机位。

评审绳由当前洞室的真实墙面射线落锚，经 `placeRopeAt` 和现有路径生成器完成；不是额外画在截图上的线。定位、交叉资格切换等只存在于缓存预览，测试脚本不进入手机包。

先看同机位1/2/3根固定绳，再检查转灯、关灯、真实游动、鱼撞网变形、整网拆除与图形上下文恢复。浏览器结果不代表微信真机性能。

`npm run rope:volume` 包括网格/缓存CPU检查与浏览器场景检查。另运行 `fish:volume`、`rope:check`、`fish:check`、`typecheck`、`package:check` 检查共享着色器、既有交互和包体。

浏览器已检查1/2/3根同机位全数保留三维、既有路径不变、静止缓存、转灯/关灯、无鱼编网、删除和单/双绳上下文恢复。真实7根网捕获鱼后，记录实际drawElements所用GPU顶点，与共享真实受力路径生成的预期逐点对照，误差为0；挣扎从约11单位变形到29单位，管体随之更新，冻结接触不重复上传。真实剪网使相连网和GPU管体一起清零。

单绳场景中真实AI约2.97秒游动126.23单位，路径未变、未伪造snag；本次鱼并未跨过绳线，不宣称完成了横穿。另有明确的渲染摆位检查：把鱼放到绳中段、关阴影以隔离影子影响，临时移除/恢复同一绳对象，鱼身中央像素差为0，鱼外绳段平均RGB差约22.36，确认管体被鱼身正确遮住。这不代表绕鱼体的完整三维缠绕。

602.62单位长的双墙锚样例使用330顶点、624三角、15,624字节网格缓冲；本次7根受力网为11,584三角、282,552字节，静止帧不重传。上一轮引入的MSAA仍是较大的额外渲染开销：1001×563的三维画布，按4样本估计额外约17.2MiB颜色/深度缓冲，单绳场景统计由约16.1MiB增加至33.3MiB；这是缓冲估算，不是实测总显存或手机帧率。已把抗锯齿样本数计入统计，真机需再验收。
