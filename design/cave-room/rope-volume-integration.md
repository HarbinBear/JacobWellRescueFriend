# 固定引导绳体积接入 · 2026-11-12

本轮在实体鱼之后推进绳索的受光与遮挡，先覆盖两端挂墙、尚未编网、全段入水的固定引导绳。

## 表现与玩法边界

绳芯沿已有 `rope.path`，中心保持 z=0，圆截面围绕它展开。不要为了展示厚度加粗成管道，也不要添加与真实路径脱离的前后摆动。原来的落锚、绕墙路径、铺绳、编网、拆绳、碰撞和存档都继续使用。

绳与洞壁、实体鱼共用三维相机、深度缓冲、手电阴影和岩面回光。共用实体鱼着色器的照明计算，但绳用宽而弱的哑光高光及较小阴影偏移；鱼的材质参数保持原值。二维层仅跳过本帧已经画出的立体绳段，墙锚与绳结保留原绘制。

首次近景中细绳有明显单采样台阶，三维画布现申请MSAA抗锯齿，桌面实测获得4样本。`volumeAntialias` 控制启动时是否申请，修改后需重启游戏；平台不支持时照常渲染。此改动也平滑鱼体/洞壁轮廓，没有增加绳半径或改洞形。

静止绳网格复用 GPU 缓冲。路径内容、对象身份、编网资格或可见选择变化时才重传；其版本参与洞室画面缓存，避免无鱼场景剪掉绳后留下残影。整根超出预算或不受支持时整根回退，不只画前半根。

## 必须保留的限制

- 单条引导绳原本不拦鱼或人；只有编成 woven 网后才参加绳网碰撞。此次不宣称立体缠绕或三维碰撞完成。
- 编网、腰扣牵引、铺设中的活动绳、跨水面的绳仍走原二维画法。编成网后整根从立体切回二维，会有材质差别，后续应整体统一。
- 潜水员、墙锚、绳结仍在二维前景，尚不能表现绳绕过手掌或身体背面的完整遮挡。
- UI 入口与探索菜单是流程阶段的临时版本；用户明确指出它与圆形仪表、潜水装备控件风格不一致，已记入 ToDo，不能视作美术定稿。

## 评审方式

`npm run shaders && npm run karst:preview` 后，打开本地预览的 `/node_modules/.cache/karst-review/live/game.html?rope-volume`。侧栏可切原平面绳、宽景、近看与墙锚机位。

评审绳由当前洞室的真实墙面射线落锚，经 `placeRopeAt` 和现有路径生成器完成；不是额外画在截图上的线。定位、交叉资格切换等只存在于缓存预览，测试脚本不进入手机包。

先看同机位开关对照，再检查转灯、关灯、真实游动、编网资格变化、移除与图形上下文恢复。浏览器结果不代表微信真机性能。

`npm run rope:volume` 包括网格/缓存CPU检查与浏览器场景检查。另运行 `fish:volume`、`rope:check`、`fish:check`、`typecheck`、`package:check` 检查共享着色器、既有交互和包体。

浏览器已检查开关与转灯、关灯、稳定缓存、无鱼时编网资格切换、删除和上下文恢复；实际AI推进约2.87秒、鱼移动96.37单位，绳路未变。另有明确的渲染摆位检查：将鱼放到真实绳中段，关阴影以隔离影子影响，临时移除/恢复同一绳对象后，鱼身中央像素差为0，鱼外绳段平均RGB差约16.66，确认绳没有叠在鱼表面。该摆位不代表AI横穿、拦鱼或三维缠绕已完成。

602.62单位长的双墙锚样例使用330顶点、624三角、15,624字节网格缓冲，静止帧不重传。MSAA才是本轮较大的额外渲染开销：1001×563的三维画布，按4样本估计额外约17.2MiB颜色/深度缓冲，当前场景统计由约16.1MiB增加至33.3MiB；这是缓冲估算，不是实测总显存或手机帧率。已把抗锯齿样本数计入统计，真机需再验收。
