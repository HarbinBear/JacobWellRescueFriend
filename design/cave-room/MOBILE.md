# v1.0.20 手机首帧与岩体受光

## 已报告的手机异常

进入“岩体试跑”后只画出人物，岩体和UI不出现，画面停在第一帧。手机日志为 `ReferenceError: performance is not defined`，指向 `RenderCaveRock.ts` 原188行。

原因是岩体CPU耗时统计直接使用浏览器 `performance.now()`，微信手机环境没有这个全局对象。实际绘制顺序先画人物、再画岩体、最后画HUD；异常发生在岩体入口，HUD和主循环末尾下一帧调度都没执行。不是地图通路或手机性能引起。

这是岩体接入代码的兼容性漏项。旧资源测试运行在Node全局里，那里提供performance；旧真实浏览器检查也提供该对象，二者都没有覆盖这台手机的条件。

## 修复

岩体计时三处统一改用安全函数：检查浏览器计时对象与now方法是否存在，诊断接口抛错或返回无效值时也不让异常流出，缺失时回退Date.now。耗时统计不参与游戏模拟；使用低精度时间只影响CPU毫秒统计，不降低画质。计时差取非负值。

没有用空catch包住整帧，也没有暂停模拟、关闭岩体或隐藏UI来规避错误。

新增检查：

- 在无performance全局的独立VM中加载并运行真实岩体模块。
- 测试performance为null、空对象、now非函数、now抛错和返回NaN的环境，帧绘制及资源管理继续执行。
- 实际游戏浏览器进入试跑前移除performance，再走倒带、入水、播放、移动、扣氧、工具轮盘开始/结束铺绳及退出流程。
- 探测真实Canvas文字调用，确认岩体绘制之后HUD仍被执行；同时检查持续动画而非只看第一帧截图。

## 继续落入版本的受光改进

不重新制作已经认可的贴图，不新增资产，也不降低透明边缘抗锯齿。保留三个局部遮挡采样及原采样密度。

- 高光视向改为离线岩体投影 `P(x,y,z)=(x+.18z,y-.26z)` 对应的正交视向 `normalize(-.18,.26,1)`，不再假设正面+Z相机。侧面反光与实际几何方向更一致。
- 高光按入射角平滑衰减，背光面不再仅因半角向量而发亮，接触AO较暗处反光减弱。
- 局部遮挡采样不越过近处光源；贴图边界外的夹边数据不当作真实遮挡物。消除靠得很近时和资产边界附近的错误遮挡条件。

这些是沿现有矿物断面岩体的小步修正，不是新的美术定稿或全图替换。

## 复验

```sh
npm run cave:check
npm run typecheck
npm run game:preview
npm run cave:browser
npm run package:check
```

原救援、体力、背包与窗口适配检查仍需保持通过。包体保护继续沿用v1.0.19，修改没有增加任何运行图片；静态候选仍约7.75MiB。

浏览器中移除performance是针对这次报错的验证，不代表真实微信手机GPU、离屏画布合成、最终编译包体或视觉已经验收。用户需在开发者工具重新编译并生成新预览，主菜单进入“岩体试跑”。私有开发者配置保留用户当前修改，不擅自更改或提交。
