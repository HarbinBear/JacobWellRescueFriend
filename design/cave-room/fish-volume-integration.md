# 实体鱼接入记录 · 2026-11-12

用户认可上一轮钟乳石与弯曲石幔后，本轮选择推进鱼与三维洞室的视觉统一。洞腔生成、沉积样例、岩面材质和原有灯光参数均未调整。

## 本轮结果

食人鱼与好奇鱼改为程序生成的实体网格：侧扁鱼身、双眼、鳃沟、嘴缝、薄鳍、鳍条和分叉尾；尾部前后摆动，转向有轻微滚转。每条 800 顶点、1,308 三角，不使用新贴图。体色为低饱和银灰、深背与浅腹，手电和洞室实际回光决定受光。

鱼的中心仍在 z=0，身体与鳍有约 ±11 单位厚度。原有 XY 移动、鱼头/绳结互动点、碰撞、AI、眩晕、绑缚与存档继续使用。网中挣扎从真实 contact 读取，不新造一套鱼网状态。没有增加随机视觉深度来掩盖平面规则。

鱼与洞室共享相机、深度缓冲、手电阴影和岩面回光落点；屏外但仍在灯程中的鱼也参与阴影。二维切面纹理增加有符号 alpha 通道，用于阻止鱼体前半穿到岩石剖面外；原岩面读取的 R 通道字节保持不变。

二维角色、绳结、交互提示单独绘制前景，经过同一暗罩后再合成，防止洞室补光覆盖在它们身上。角色的原有近身可见度保留。鱼着色器失败不会拖垮洞室，能单独回退二维；上下文恢复会重建。

## 评审与检查

构建：`npm run shaders && npm run karst:preview`。本地已有服务器时打开：

- `/node_modules/.cache/karst-review/live/game.html?fish-volume`：原洞室、两条真实 AI 鱼。
- 同一页面侧栏“实体鱼 / 原平面鱼对照”切换；“实体鱼 · 真实入网”创建当前墙面的真实锚网，推进实际鱼碰撞取得 snag。

检查：`npm run fish:volume`、`npm run fish:check`、`npm run rope:check`、`npm run karst:volume`、`npm run world:regression`、`npm run typecheck`、`npm run package:check`。

新增浏览器检查包括实际游动与真实 snag、开关手电、二维回退、绑缚/眩晕显示、岩石切面裁切、鱼 shader 故障注入、上下文恢复和移除鱼后的旧画面清除。绑缚/眩晕截图只验证显示，实际操作提交由既有 fish:check 覆盖。临时截图、报告与 8 秒游动视频位于被忽略的 `node_modules/.cache/karst-review/fish-volume/`。

## 限制与下一步

- 绳索和潜水员仍是二维前景；绳子目前整体叠在实体鱼上，不是管状绳绕过鱼身的真实深度。本轮真实入网截图中，亮色绳结仍过于抢眼。下一步先处理管状绳的受光与接触关系，再做潜水员。
- 仅两种鱼换成实体。每帧最多 24 条（屏内优先），超额和其他种类继续使用原画法，暂不宣称所有生物完成统一。
- 鱼使用共享落点的半球近似间接光，不是完整路径追踪。薄鳍目前是实体薄膜，尚未实现半透明组织或鳞片纹理。
- 活跃鱼会使洞室颜色/阴影重新绘制，新增前景画布占 `主画布宽×高×4` 字节；有符号切面额外占约 0.9 MB 显存。桌面通过不代表手机性能通过，需要微信真机检查。
- 本轮静态包体估算约 8.20 MB，仍低于 8 MiB；不是微信工具编译后的官方大小。
