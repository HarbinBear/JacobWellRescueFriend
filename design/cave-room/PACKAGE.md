# v1.0.19 包体与岩体手机资源预算

## 包体修复

用户报告微信手机预览因代码包超过8MB失败。本轮按项目 `packOptions` 检查，修改前候选文件合计9,477,212字节，约9.04MiB。新增岩体贴图约1.94MiB，同时0.87MiB的地图制作原图也在打包目录中。

处理没有删掉或降级已认可的岩体：

- 排除 `texture/`：`Well.png` 仅供离线生成 `src/world/mapData.ts`，实际游戏读取已经生成的地图数据，不加载这张原图。
- 排除私人项目配置、开发用 `package.json` 和原始 `.glsl` 文件。运行实际使用的 `.glsl.ts` 着色器模块保留，未关闭手电或法线。
- 8张运行PNG使用Pillow无损重编码，共节省424,863字节。每张图的宽高、模式和解码像素字节全部一致，包括法线方向和半透明抗锯齿覆盖率。家场景图片仅改变编码及非渲染元数据，不改变像素。
- 开发原图仍保留在项目中，已认可岩体原始参照仍在 `design/cave-room/`，没有删除。

最终候选约7.75MiB。这个数字是源码文件与资源的静态估算，不是微信官方编译包体；不能用于承诺真实手机帧率或替代开发者工具的最终统计。

`npm run package:check` 按本项目打包规则统计，并检查必需运行文件没有被误排除。`npm run build` 已挂接同一预检查，超过8MiB前的128KiB预留线时失败。该检查是早期保护，不是编译器模拟器；微信开发者工具的结果始终优先。

## 官方预览验证边界

本轮已尝试用已安装开发者工具执行实际 `preview`，但工具提示服务端口关闭，编译流程未启动，也未生成手机二维码。没有擅自更改这个安全设置。

用户可以直接在开发者工具重新编译，再点击“预览”，从主菜单进入“岩体试跑”。如果需要由助手自动取得官方包体与预览二维码，需要用户在“设置 → 安全设置”手动开启服务端口。

## 继续完成的运行优化

- 岩体贴图从全局启动预载改为进入关卡期间预热。主菜单和普通地图不解码这4张岩体图。
- 退出关卡释放岩体图片缓存、3张表面纹理、距离纹理、VBO、shader程序与计时查询，缩小离屏帧缓冲；不卸载家场景资产。再次进入会重建完整资源。
- 岩体表面只画相机与洞室相交范围，裁剪严格对齐原来的超采样像素网格，保留1像素边缘保护。采样密度不变，不以降低抗锯齿换性能。
- 相机、光向、位置和所有参与受光的参数完全相同时复用上次表面；转灯、移动、改画质、改光照或上下文恢复时重新提交。不是冻结角色或游戏模拟。

活动岩体资源的理论解码缓存18,579,456字节，表面纹理13,934,592字节；退出后相关缓存引用与GPU资源计数均归零。该数字是资源预算，不是操作系统实测内存释放时刻。

```sh

npm run cave:check
npm run typecheck
npm run game:preview
npm run cave:browser
```

新增资源回归验证原采样网格、惰性加载、静止复用、转灯更新、退出与再次进入、上下文恢复以及家场景缓存不受影响。真实浏览器依旧按菜单、倒带、入水和播放流程运行，检查真实扣氧、移动、轮盘开始/结束铺绳、退出存档恢复及岩体资源清理。

原下潜、救援、体力、背包和窗口适配回归仍通过。微信手机视觉、真实GPU帧耗时、峰值内存和官方预览包体仍待用户设备验证。本轮以解除手机测试阻塞和降低资源负担为优先，没有重画已经认可的岩体；细部法线和更多不同洞室继续沿原基线深化。
