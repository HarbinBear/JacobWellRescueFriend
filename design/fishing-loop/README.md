# 捕鱼之后：两个可比较的循环候选

2026-11-12。**这是供共同决策的方案，不是已接入玩法，也不是美术稿。** 用户尚未决定鱼用于交易、食物、收藏还是其它用途；本轮不擅自决定正式价格、掉落或长线成长。建议先比较“带回一趟能力提升”与“认识一个新物种”这两个明确动机。

## 当前真正能做什么

实际可玩路径是：灯光诱导/接近鱼 → 多绳织网逐渐缠住 → 近身敲晕 → 系鱼身绳与腰扣 → 拆网 → 把同一条实体鱼拖到岸上。鱼不是背包数字，眩晕不是死亡。连续世界不因上岸重置；快速回岸只带回玩家，鱼留在原处。

鱼档与装备铺目前都是占位面板。旧撤离模式有古物入仓、卖货、金币和购买逻辑，默认连续世界没有把这些入口接通；没有捕鱼收入、收鱼范围判定、买方所有权或交付记录。已有可消费币种只有 `coins`，初始100；名声没有增长逻辑。

## A：卖鱼，改变下一趟能力

推荐先试此项来回答“辛苦拖回来，到底得到什么”。保持一个鱼档、一种货币和一个明确可买的升级。

| 目标节奏 | 玩家做的事 | 实际意义 |
|---|---|---|
| 0–1分钟 | 出发前看见鱼档的报价和一只大气瓶的固定价签 | 出发时已知道这趟差多少钱 |
| 1–5分钟 | 在浅洞诱网、敲晕、绑好一条好奇鱼 | 使用当前已存在的捕法 |
| 5–8分钟 | 拖着同一条鱼回鱼档，鱼确实抵达后才允许交付 | 运回过程构成风险，不是玩家站岸上就全部卖出 |
| 8–9分钟 | 交鱼、付钱拿气瓶，在岸上实际换装 | 氧气上限立即变化，余额与实体鱼同步保存 |
| 9–10分钟 | 沿原有绳网去上一趟犹豫过的分岔 | 再出发有具体理由 |

十分钟是**待试玩验证的目标**，不能用预先绑好的鱼冒充完成捕获。第一轮也不扩完整随机货架。

一个可测的算例：沿用现有初始100金币、大瓶普通价120和单瓶容量300；**仅在隔离评审中暂设好奇鱼60金币**。成功交一条后余额160，买大瓶后40；若从保底单小瓶换成单大瓶，气量上限由120变为300。中瓶只需40，初始100已经买得起，所以“先抓一条才能买中瓶”在现有经济里不成立。

60只是使首次收益可见的试验值，没有证明它适合长线。若后续目标是350金币的续航脚蹼，买大瓶后还差310，按同价需要6条鱼；如果每条连捕带运要十分钟，这可能过于重复。应先记录实际捕获时间、回程时间、成功率和玩家下次目的，再决定鱼价、固定委托加价或升级节奏。不能一开始用多个新币种掩盖这个问题。

## B：观察、记录、放回原来的水域

收益是“我对这个地方有了一个具体发现”，而不是卖掉一条鱼。仍然只做现有好奇鱼与银鳞鱼群两条记录，暂不建水族馆。

同样捕获并实际拖回，在营地观察池记录鱼的外形、地点及一句可验证的行为。记录完成后把**原鱼**带回浅水、解开鱼身绳，看它重新游动。下一条记录提示另一种鱼的不同捕法，目标从重复数量转为认识新的行为。

记录不是第二种可消费货币；首次记录同种鱼才填一个位置，反复抓同一条不反复领奖。第一版只比较玩家是否愿意为下个发现再次出发。若记录本身不足以抵偿拖运，再共同决定是否加入设备借用/调查委托，不能先许诺一套尚未存在的奖励。

这条方向更适合留白和场景叙事，但也可能让玩家觉得“忙了一趟只换一行字”。这是必须实玩验证的风险。**当前干岸解绑会把未绑鱼夹回水面，不能当成自然放生已经做完**；原型必须在真实浅水位置解绑，或另做放生过渡。

## 其它用途先放在哪里

| 用途 | 可以提供什么 | 现在不先做的原因 |
|---|---|---|
| 烤鱼/吃鱼 | 营地生活、角色关系或短时状态 | 当前没有饥饿/食物效果，普通补气已免费；先做烤鱼动画也不能自动形成收益 |
| 水族馆 | 保留具体个体，长期观察和空间变化 | 需要个体身份、展示场景和持久所有权，明显大于两条观察记录的成本 |
| 赌博 | 不确定回报与紧张感 | 尚无玩法定位；给既有金币加随机输赢不能回答为何捕鱼和为何探索，不列入首个原型 |
| 定向委托 | 给下一趟明确目标，减少只刷最容易的鱼 | 可在A验证成立后试一张固定委托，先不扩每日任务/多币种 |

## 接入前的真实限制

现有商品数据：小/中/大瓶0/40/120金币、容量120/200/300；续航脚蹼350，速度×0.95、呼吸耗氧×0.85；竞速脚蹼400，速度×1.2；8格背包300。它们是旧注册表数值，不是已认可的捕鱼平衡。

- 连续营地充气免费，快速回岸及死亡会补满。不能直接照搬旧“每次下潜消耗气瓶”的经营成本；当前章节反复使用气瓶、跨章节如何处理要另定。
- 绳包仍不限制绳量，电池尚未真正应用/消耗；不要把它们作为现阶段有意义的奖励。背包扩容也不提高实体鱼拖运容量。
- 旧购买脚蹼/潜水衣只改装备选择，效果等下次下潜应用。连续世界上下岸不重启下潜。必须单独实现岸上换装，不能调用会消耗气瓶、清空背包的整套旧出发逻辑。
- 旧随机8件货架可能让首个升级目标根本不出现。首个原型固定一个商品，不混入随机刷新与特价。
- 解腰扣只解牵引，不解除鱼身绳。`bound` 既不代表玩家持有，也不代表已经交付；需要独立交付条件。
- 当前鱼的ID只在本世界递增。跨章节凭据不能只用裸 `worldId`，同一种子重复开局也不应复用旧领取凭据。
- 审计发现未绑鱼的网捕状态没有进入存档；另有GM生成鱼缺少稳定ID。这两项应先修，不能在不可靠的持有状态上叠收益。

## 最小实现与验收顺序

1. 先保证鱼、网、牵引和存档一致，重载不白抓、不松网；自然回岸和快速回岸分别验证。
2. 一个鱼档只识别真实抵达接收范围的那条鱼，显示对象和报价；不按玩家位置远程收鱼，不把鱼转换为普通古物背包条目。
3. 用户确认A或B后，再实现对应交付结果。A需把删除/移交鱼、清理相关绳引用、交付凭据、金币放在**同一份连续世界快照**提交；保存失败时整体回滚。不能只调用旧 `addCoins` 然后另写旧经济档。
4. A只接一种当场生效、续档仍有效的升级；B只接两种首次观察记录与原实体浅水放生。随后做完整捕获→拖回→结果→下一趟试玩。
5. 必测重复点击、确认前鱼移出范围、鱼仍在远处、存储写入失败、交付后立刻退出/切后台、重载、换地图、死亡/快速回岸、鱼仍被多条绳引用。不用大结算屏遮住状态错误。

共同决策只需先选“现金提升下一趟”还是“发现与记录”，之后再谈是否混合。人物美术、岸上3D化和完整经济平衡不作为这个验证的前置大投入。
