# 捕鱼持有状态与续档

2026-11-12。修复真实玩法缺口，不新增鱼价、交付或经济奖励。

## 原来的问题

未绑鱼进入织网后，捕获线程、挣脱进度和网的受力弹簧存在 `RopeDynamics` 的内存对象图里。连续世界只保存了鱼与绳路，退出续档会丢掉这层联系；仅保存 `bound` 无法解决，因为鱼可以先被网缠住、尚未绑鱼身绳。

另一个问题是 GM 生鱼未分配 `worldId`，鱼群也没有逐个编号。将这类鱼绑上牵引绳后，存档端点无法找到恢复后的实体。

## 现在保存什么

- 同一份连续世界快照增加可选 `fishNet`，保存鱼ID、绳索索引/线程ID/路径校验、接触线程、部分缠绕积累、挣脱和冷却进度、受力弹簧及其是否仍在运动集合中。不复制 WeakMap、旧对象指针，也不新增绳路。
- 恢复先重建鱼和绳、接回牵引端点，再重置临时网状态，最后将捕获接回新的网组。读档后继续原物理过程，不重置挣脱计时，不靠鱼的位置猜测是否被捕获。
- 生成、保存、恢复统一处理本章节鱼ID：合法ID保留，新鱼获得唯一正整数，计数器不会因清空鱼而倒退。重复ID拒绝，以免把绳接到另一条鱼。
- 读取主档时预检鱼引用、网引用、数值和探索位图完整性；损坏则尝试完整备份。预检不改当前世界。新快照也先检查，再写备份和主档；失败沿用现有保存失败提示，不主动删除旧档。顺带修复坏探索位图主档覆盖好备份的旧缺口，避免此时主档写入再失败便两档皆失。
- 老档没有 `fishNet` 仍可继续；无ID的旧自由鱼补编号，但已经丢失的历史捕网状态无法凭空找回。旧档若含无法解析的鱼端点，优先使用有效备份，不猜绑。

仍不把“被网缠住”“已绑鱼身绳”当成已交付或玩家所有权。跨章节交易凭据、交付去重和收益保存是后续独立课题。

## 验证

`npm run fish:save`：真实GM按钮及鱼工厂；五类鱼共2100帧逐帧序列化、预检和重建；完整恢复后的后续受力与不中断运行一致；部分缠绕、挣脱冷却、眩晕/绑缚、双网拆除、重复恢复；真实WorldSave的旧档兼容、坏主档回退、写入失败及非法运行引用不覆盖好档。

`npm run shaders && npm run karst:preview`，本地服务提供项目根目录后运行 `npm run fish:save:browser`。使用独立浏览器档、真实game.ts，不触碰用户存档：

1. 实际扫掠入网，确认鱼未绑、未晕且网发生受力形变。
2. 通过真实触摸菜单保存退出，再点主菜单继续。鱼、绳路和捕获快照完整一致。
3. 继续真实主循环，挣脱进度和鱼动作前进。
4. 通过动作盘选中网柄，在命中帧拆除整网。
5. 再保存、继续，同一条鱼自由游动，网与捕获不复活。

截图及报告位于忽略缓存 `node_modules/.cache/fish-net-save-browser/`。这是桌面浏览器和原生API模拟验证，微信真机存储与性能仍需实测。
